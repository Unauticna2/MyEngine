MYENGINE 2.5 — R20: ЛЁГКИЙ МЕТАЛЛ И ПРОВЕРКА ИГРОКА
R21 добавляет отправку с Android и пароль владельца: см. SMS_ANDROID_R21.txt.
Для актуальной настройки сервера используй инструкцию R21.
15 октября 2026

УСТАНОВКА
Закрой игру и редактор. Распакуй MyEngine2_Metal_SMS_R20.zip с заменой
в папку движка F:\Users\User\Desktop\MyEngine, где engine_runtime.py.
Это накопительное обновление R14 → R20; архив не заменяет твой проект MyGame.
Если R14–R19 уже запускается, пересобирать EXE не нужно. Экспортированную
игру собери повторно, чтобы в неё попали новые Python-модули и шейдер.
Полный MyEngine2_5.zip по-прежнему содержит исходники; для установки
с нуля нужно собрать EXE через build.cmd на Windows, как описано в README.

МЕТАЛЛ
Выдели полигональную модель → Inspector → Metal / cheap reflections:
  Metallic = 1
  Roughness = 0.15
  Reflection strength = 0.65
Нажми Apply changes и сохрани сцену. Metallic=0 сохраняет старый материал.
Для более матового металла увеличь Roughness, например до 0.7.
Цвет объекта задаёт оттенок металла. Модель должна иметь корректные нормали.
Демо в папке движка: start_editor.cmd map-metal-r20.json
Слева обычный материал, в центре полированный металл, справа грубый металл.

Это один отражённый луч на металлический пиксель и максимум 8 ближайших
упрощённых объектов. Луч пересекает их мировые ограничивающие коробки,
берёт цвет объекта или процедурного окружения. Есть блик и эффект Френеля.
Это приближённые отражения: точные треугольники, отражённые текстуры,
фактическая skybox-картинка и многократные отскоки не рассчитываются.
Roughness расширяет блик и ослабляет отражения коробок; настоящего размытия
из множества лучей нет. Воксельные материалы пока не получают металлический
шейдер; воксельные объекты могут отражаться как коробки с цветом объекта.

В корень JSON сцены можно добавить бюджет:
  "reflections": {"enabled": true, "maxObjects": 4, "distance": 25}
maxObjects: 0–8. distance: 1–500. enabled=false убирает отражения объектов,
но сохраняет дешёвое окружение и блик. Reflection strength=0 убирает
отражённый луч для конкретного материала. По умолчанию бюджет: 8 / 40.
Настройки materials сохраняются в сцене, дубликатах и префабах.
Цена зависит от разрешения и площади металла на экране; FPS не обещается.

ПРОВЕРКА ИГРОКА ПЕРЕД ВХОДОМ
1. Подготовь сервер из MyEngine_PlayerIdentity_Server_R20.zip по его README_RU.txt.
   Его можно заново экспортировать из редактора:
   Assets / extensions → Коммерция / генератор сайта → Сайт и кнопки →
   Проверка игрока / SMS → Экспортировать сервер для Render.
2. Автор заносит на сервер точные playerId, productId, certificateId
   и телефон игрока после проверки покупки или выдачи доступа разработчику.
3. В «Проверка игрока / SMS» укажи HTTPS-адрес сервера и включи
   «Требовать SMS для доступа…». Сохрани и перезапусти Play.
4. Для новой кнопки в UI Blueprints выбери шаблон
   «Войти после проверки игрока / SMS» и нужный товар.
   В Load scene укажи сцену игры. Key должен совпадать с остальными
   узлами доступа этого товара. Apply to UI → Ctrl+S → Play.
   Для существующего графа добавь условие вручную: выбор шаблона не
   перезаписывает уже существующий граф кнопки.
5. Нажми кнопку входа: откроется выбор JSON-сертификата. После выбора
   сервер проверит реестр и откроет браузер. Введи привязанный телефон,
   нажми «Получить SMS-код» и введи полученный код. Вернись в игру
   и нажми кнопку входа ещё раз — теперь загрузится сцена.

Граф: UI Click → Branch; Player verified.value → condition;
True → Load scene; False → Import certificate.
Пример: examples/R20/player_gate.blueprint.json и player_gate.py.
Он использует slide=1, element=2, product=deluxe, key=purchase,
сцену scenes/room1.json. Меняй эти параметры под свой интерфейс.
Пример не прикрепляется к сцене автоматически и не заменяет ui.py.

Если требовать SMS включено, TransactionHasAccess / Access unlocked тоже
требует свежий ответ этого сервера. Один локальный сертификат или запись
state=succeeded не обходит проверку. При выключенной настройке сохраняется
режим R19. Player verified всегда означает именно серверную проверку SMS.
Настройки: payments.json → identityApi (HTTPS-origin), identityRequired (bool).
Секреты SMS и DATABASE_URL запрещено класть в проект или публиковать в GitHub.

ПОВЕДЕНИЕ СЕССИИ
После ввода правильного кода сессия действует до 12 часов. При запуске
игры её всё равно нужно подтвердить ответом сервера. Далее опрос идёт
раз в 15 секунд; при ошибке ответ считается непроверенным, а без свежего
ответа более 30 секунд условие доступа становится false. Нужен интернет.
Входной Branch проверяет вход в сцену, но сам по себе не выкидывает игрока
из уже открытой сцены. Для такого поведения проверяй условие и во время игры.
Копирование поля verified=true в файл не открывает вход. Полностью защитить
локальную Python-игру от переписывания кода этот механизм не может.

Сброс на компьютере: закрой игру и редактор, сделай копию папки
%LOCALAPPDATA%\MyEngine2\Certificates. Для нужной установки убери файл
<хеш>.identity.json; для локальных разрешений R19 — соответствующий <хеш>.json.
Общий запрет доступа выполняется на сервере через revoke-player или
revoke-certificate. Удаление локального файла не удаляет серверный реестр.

SMS НЕ ОЗНАЧАЕТ ОПЛАТУ
SMS подтверждает доступ к привязанному номеру и зарегистрированной записи.
Состояние банковской операции не меняется; paid_once не вызывается.
Регистрация сертификата — отдельное действие автора, не публичная кнопка.
Для собственного аккаунта можно зарегистрировать сертификат разработчика
«оплата не требуется», без перевода денег самому себе.

ЧТО УЖЕ ПРОВЕРЕНО
107 автоматических тестов, включая реестр, разные токены браузера/игры,
неверный телефон, ограничение попыток кода и отправок, отзыв доступа,
перезапуск, ошибку сети/диска, подмену локального файла, Blueprint-условие,
материалы, каталог и предыдущие функции. SQL-тесты выполнялись на SQLite.
Оба GLSL120-шейдера собраны и металлические сферы отрисованы на Mesa OpenGL.
Нативный Windows-редактор, твоя видеокарта, реальный PostgreSQL на Render
и доставка настоящей SMS в этой среде не проверялись. Сервер не опубликован;
SMS по умолчанию выключены до настройки провайдера и реестра.
