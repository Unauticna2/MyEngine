MyEngine 2.3 — инструкция по обновлению
====================================

БЫСТРЫЙ ЗАПУСК
1. Сохранить сцену и закрыть Editor, Hub и игровые окна.
2. Распаковать обновление поверх MyEngine 2.2 с заменой файлов.
   Сначала сделать копию своих изменённых исходников/демо-сцен: архив их обновляет.
3. build.cmd. Если MyEngine2.exe занят, скрипт оставит новый EXE в
   build/MyEngine2.new.exe и попросит закрыть окна; процессы не убиваются.
4. start_hub.cmd. Отдельный пример новых возможностей: start_showcase.cmd.
Полный архив подходит и для новой установки; setup_python.cmd нужен один раз.
Готового скомпилированного Windows EXE в архиве нет.

ВОКСЕЛИ
На границах ячеек добавлен неподвижный синусный epsilon примерно 0.00001 ячейки.
Он меняет выбор граничной ячейки, не анимирует геометрию, цвет или глубину.
DDA теперь пересчитывает расстояния до граней, вместо накопления суммы шагов.
Это устраняет один источник погрешности длинного прохода и не создаёт
временного мерцания. Не является обещанием исправить любые ошибки драйвера
или пересечение двух разных моделей в одной плоскости.
В scene JSON: "voxelBoundaryBias": 0.00001. Допустимый диапазон 0..0.001;
0 отключает синусную добавку, минимальный защитный epsilon остаётся.

СКАЙБОКС
Кнопка Skybox в редакторе → Choose / import panorama → Apply → Save.
Одна PNG/BMP читается как сферическая панорама (обычно 2:1).
JSON сцены:
  "skybox": {"texture":"assets/sky.png", "yaw":0, "exposure":1}
Или шесть квадратных PNG/BMP:
  "skybox": {"faces":{"px":"assets/right.png","nx":"assets/left.png",
    "py":"assets/up.png","ny":"assets/down.png",
    "pz":"assets/front.png","nz":"assets/back.png"},"yaw":0,"exposure":1}
Можно вынести этот объект в .sky.json и указать его путь в skybox.
Пути внутри .sky.json тоже относительно корня проекта.
Python: self.world.set_skybox({"texture":"assets/sky.png","yaw":45})
Python: self.world.set_skybox(None)
Фон поворачивается вместе с направлением камеры, не перемещается вслед за
позицией, не освещается лампой, не перекрывает глубину моделей и вокселей.
Вложенный skybox/skyboxmodel.obj содержит только комментарии и mtllib,
без геометрии. Поэтому демонстрация использует skymask2.png напрямую.
Исходные skymask2.png и sunmask.png сохранены без изменения; sunmask не
подключается автоматически как солнце. Отдельной модели фону не требуется.

ГАЛОЧКИ В INSPECTOR
Omit model in build — объект, скрипты и физика остаются, изображение скрыто.
Editor only — объект целиком исключается из экспортированных сцен.
Нажать Apply changes, затем Save / Build game.
Редактируемая сцена не изменяется при сборке. Для BoxCollider без заданного
размера перед удалением модели сохраняются её габариты/смещение коллайдера.
Для MeshCollider, VoxelCollider и 4D-объекта с физикой исходная геометрия
остаётся в данных: она нужна коллизиям/выбору W-среза, хотя не рисуется.
Модель/текстура убираются из Data, если не нужны другим собранным сценам
или явно указанным Python-путям. Для динамически составленных путей добавь
в сцену "buildKeepAssets":["assets/MyModel.obj"].

ФИЗИКА ПЕРСОНАЖА
Кнопка Player physics → fly / walk / script → Replace player physics.
Поля: размер бокса, смещение относительно камеры, масса, скорости и прыжок.
Walk: WASD, Shift, Space; мышь/стрелки — направление. Капсулы пока нет;
используется вертикальный бокс с нативным ASM-решателем.
В режиме script выбирается Python-файл, self.entity у него — камера.
Не подключать одновременно старый scripts/player_walk.py к отдельному объекту
и новый контроллер walk: два контроллера будут задавать одну скорость.
Пример управления во время игры:
  self.world.camera.configure_physics("walk", size=(.6,1.8,.6),
      center=(0,-.7,0), mass=75, speed=4, sprint=8, jump=5)
  self.world.camera.configure_physics("fly")
  self.world.camera.configure_physics("script", script="scripts/character_custom.py")
Пример пользовательского контроллера: scripts/character_custom.py.
Физика персонажа включается в Play; камера редактора остаётся свободной.

BLUEPRINTS → PYTHON
Кнопка Blueprints. В новом графе готов пример вращения на 30 градусов/сек.
Выбрать тип → Add node. Перетаскивать заголовок узла мышью.
Нажать выходной кружок, затем входной того же типа.
Белый = выполнение, зелёный = число, фиолетовый = bool.
Параметры выбранного узла справа, Apply parameters применяет JSON.
Подсказка объясняет каждый узел, Python preview показывает результат.
Save graph сохраняет *.blueprint.json, Generate Python создаёт/обновляет *.py.
Генерируется только участок:
  # region MYENGINE_BLUEPRINT
  ...функции start/update/fixed_update...
  # endregion MYENGINE_BLUEPRINT
В новом файле создаётся класс Script, вызывающий эти функции. В уже созданном
файле код за пределами региона сохраняется. Существующий Python без этого
региона не перезаписывается: выбрать новый файл или подготовить регион вручную
и вызвать _bp_start/_bp_update/_bp_fixed_update из своего Script.
Можно прикрепить сгенерированный скрипт к выделенному объекту сразу из окна.
Пример: scripts/spin.blueprint.json и scripts/blueprint_spin.py.
Узлы: Start/Update/FixedUpdate, Number, DeltaTime, Add, Multiply,
KeyDown/KeyPressed, Compare, Branch, Move, Rotate, Rotate4D, Velocity,
Impulse, Spawn, LoadScene, Print, Destroy, Character.
Spawn позволяет указать модель и прикреплённый Python-скрипт.
Циклы связей запрещены; для повторения есть Update/FixedUpdate.
Лимит 256 узлов/1024 связей. Данные вычисляются при использовании, это не
полный аналог Unreal Blueprint с произвольными пользовательскими типами.

4D ПРОИЗВОДИТЕЛЬНОСТЬ
Постоянный фоновый worker вместо нового ThreadPoolExecutor + result() на кадр.
Очередь хранит только последний запрос каждого объекта. Готовый срез остаётся
видимым до следующего; GL-объекты и физика обновляются на потоке движка.
Предрасчитаны индексы общих вершин, отсеиваются треугольники и лишние
пересечения контуров. 12 результатов/ограниченный объём кэша повторных срезов.
На spherecube.4d, углы (20,15,0), W=0, результат одинаков: 6732 треугольника.
Локальный замер без профайлера: медиана 2.2 ≈0.854 с, 2.3 ≈0.198 с
после подготовки кэша (примерно в 4.3 раза). Это время расчёта среза,
не FPS и не замер на вашем Windows-компьютере.
Первичная загрузка ждёт полный срез; во время игры тяжёлый срез может
запаздывать за изменением W. Python-расчёт использует GIL: это асинхронность,
а не обещание параллельного исполнения Python на всех ядрах.
Слой должен быть замкнутым OBJ. Это по-прежнему физика текущего 3D-среза,
а не полноценная механика твёрдых тел в четырёх измерениях.

GITHUB ПАКЕТЫ
Кнопка GitHub packages в Hub / Editor.
Search / refresh: публичные репозитории с topic:mypakege, затем через
Next results — MyPakege_ in:name и MyPackege_ in:name, по страницам.
Оба написания поддерживаются; новое имя по умолчанию MyPackege_Name.
Автор позволяет сузить поиск. GitHub ограничивает один поиск 1000 результатами
и частоту запросов; интерфейс сообщает о неполной выдаче/лимитах.
image.png — превью, Data.txt — UTF-8 описание в корне репозитория.
Читаются также имадж.png / Image.png и Дата.txt.
Clone project клонирует проект через Git в выбранную папку без перезаписи
существующей и добавляет в Hub. Refresh projects обновляет список.
Можно указать OWNER/REPO напрямую. Клонирование не запускает Python.
Открытие стороннего проекта в редакторе загружает его Python; открывайте
проекты тех авторов, коду которых доверяете.

PUBLISH PROJECT
Из Editor: Save → Publish project. Из Hub: выбрать проект → Publish project.
1. Задать имя MyPackege_Name (латинские буквы/цифры), PNG и описание.
2. Просмотреть список файлов, двойным кликом исключить ненужные.
   Папки Builds/.git/.myengine, .env, типовые credentials/secrets пропускаются.
   Просмотр списка нужен и для остальных личных файлов с произвольными именами.
3. Prepare package: создаётся локальная проверяемая копия, package.json,
   package.zip, image.png, Data.txt и index.html. Стадия в .myengine/publish-*.
4. Git нужен для clone/push. Для публикации также нужен GitHub CLI (gh).
   Если не найдены — открыть официальную страницу установки и перезапустить Hub.
   Login to GitHub запускает официальный gh auth login в отдельном окне.
   Движок не сохраняет пароль или токен в проекте.
5. Publish PUBLIC repository создаёт НОВЫЙ публичный репозиторий,
   загружает проверенную копию, ставит topics mypakege/myengine2 и запрашивает
   GitHub Pages от main / корня. Существующий репозиторий не перезаписывается.
   Адрес: https://OWNER.github.io/MyPackege_Name/
   Это страница загрузки проекта. Windows EXE не превращается в браузерную игру.
   GitHub Pages может развернуться не сразу; при отказе интерфейс покажет
   причину и настройку Settings → Pages. Код может быть загружен успешно,
   даже если настройка Pages не удалась.
   Если push прерван, локальный Git-коммит остаётся для восстановления,
   никакого force-push или удаления удалённого репозитория нет.
Пределы: файл/ZIP до 90 MiB, суммарные исходные файлы до 500 MiB.
Публикуется редактируемый проект, не установленный Python и не весь движок.
Для Windows-игры остаётся Build game → Name.exe + Data.

ПРОВЕРКИ И ГРАНИЦЫ
45 переносимых тестов: python -m unittest discover -s tests -v.
Отдельно проверены нативная ASM-физика через ABI-обёртку, переключение
персонажа, фоновая смена среза и освобождение моделей.
GLSL реально скомпилирован и отрисован в Mesa OpenGL: скайбоксы,
перекрытие полигонов/вокселей, камера внутри вокселей, стабильность кадров.
Публичный read-only запрос GitHub API выполнен; создание репозитория/push
проверялись подменой CLI, без настоящей публикации.
Windows GUI, готовый Windows EXE и вход в ваш GitHub здесь не запускались.
