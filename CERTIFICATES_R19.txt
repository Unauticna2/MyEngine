15 октября 2026

УСТАНОВКА
Закрой игру и редактор. Распакуй MyEngine2_Certificates_R19.zip в папку
движка с заменой файлов. Это накопительное обновление относительно R14,
включающее Commerce R15–R17 и узлы видимости R18.
При обновлении с R14–R18 пересобирать EXE не требуется.
Для уже экспортированной игры сделай новый экспорт, чтобы обновились Python-модули.

ОКНО В ИГРЕ
Новый узел CertificateImport / Import certificate открывает выбор JSON-файла
Windows, затем показывает товар, ID игрока и ключ Blueprint перед активацией.
После подтверждения файл проверяется и доступ сохраняется на этом компьютере.
Окно и чтение выбранного файла работают в отдельном потоке; игровая логика
получает результат в ближайшем Update. Tkinter в собранной игре не нужен.
Одновременно открывается только одно окно. Отмена не выдаёт доступ.
Ошибка показывает сообщение, не отключая игровой скрипт.

КНОПКА ИЗ POWERPOINT
Открой UI Blueprints, выбери элемент интерфейса и действие
«Загрузить сертификат». Выбери товар, создай граф и проверь параметры узла:
  product = ID товара из каталога, например deluxe
  key = ключ операции, например purchase
  playerId = ожидаемый ID игрока, либо пусто без привязки к игроку
Для новой кнопки key по умолчанию равен product, как и у TransactionStart.
Если твоя проверка использует другой key, поменяй его в узле импорта.
Нажми Apply to UI, сохрани сцену и запусти Play.

ПРОВЕРКА ДОСТУПА
TransactionHasAccess / Access unlocked (key) возвращает true:
  - после succeeded от checkout API;
  - после импорта локального сертификата на этот key.
Подключи value к Branch.condition или напрямую к SetVisible.visible.
TransactionIs(state=succeeded) и TransactionPaidOnce по-прежнему означают
только серверное подтверждение покупки. Импорт не меняет статусы транзакций,
не отменяет ожидающую оплату и не вызывает paid_once.
После перезапуска сохранённый сертификат открывает TransactionHasAccess,
даже если новая транзакция ещё не создавалась и TransactionIs показывает idle.

ПРИМЕРЫ PYTHON
  self.world.transactions.import_certificate('deluxe', 'purchase')
  self.world.transactions.has_access('purchase')
Дополнительный третий аргумент import_certificate — ожидаемый playerId.
import_certificate возвращает только факт открытия окна; это не результат активации.
certificate_status: idle, selecting, activated, canceled или error.
certificate_error содержит текст последней ошибки импорта.

ФОРМАТ И ПРОВЕРКИ
Поддерживается JSON schema=myengine-license/v1, выдаваемый текущим сайтом.
Сертификат разработчика grantType=developer/payment.status=not_required подходит.
Также поддерживаются локальные сертификаты grantType=purchase или manual,
выданные автором. Это обновление не создаёт новые сертификаты покупки на сайте.
Проверяются JSON, уникальность полей, размер до 64 KiB, ID товара и сертификата,
licenseStatus=issued, тип выдачи, даты, необязательный срок expiresAt и playerId.
Товар должен входить в siteProducts из payments.json. Если его нет, добавь товар
в генераторе и снова подключи сайт к проекту. Файл для другого товара отклоняется.
Ключ уже активированного/созданного другого товара повторно использовать нельзя.
Поддерживаются только локальные сертификаты без подписи (signature=null).

ЧТО ОЗНАЧАЕТ ЛОКАЛЬНАЯ АКТИВАЦИЯ
JSON текущего сайта не подписан. Проверка структуры не доказывает происхождение
файла или факт оплаты: такой файл можно изменить или скопировать. Даже если
в JSON написано payment.status=succeeded или bankVerified=true, движок не считает
это серверным подтверждением. Для защищённых покупок остаётся checkout API.
Без playerId в узле файл не привязан к конкретному игроку; и проверка строки
playerId сама по себе не заменяет вход в аккаунт.

СОХРАНЕНИЕ
Активации хранятся вне проекта и сборки:
  %LOCALAPPDATA%\MyEngine2\Certificates\<хеш пути установки>.json
Перезапуск, Stop/Play и смена сцены в той же установке сохраняют доступ.
Перенос игры/проекта в другую папку требует повторного импорта сертификата.
Коллайдер и физика при SetVisible не отключаются.
