MYENGINE 2.5 — R15: КОММЕРЦИЯ И ГЕНЕРАТОР ПЛАТЁЖНОГО САЙТА

УСТАНОВКА
Закрой MyEngine. MyEngine2_Commerce_R15.zip распакуй поверх папки движка
с заменой файлов, сохранив вложенную папку templates/payment-site.
Это обновление поверх MyEngine 2.5 R14. Изменены Python-файлы редактора
и шаблон сайта; существующий EXE R14 пересобирать для R15 не требуется.
Полный MyEngine2_5.zip тоже обновлён, но для текущей установки удобнее
маленький архив R15: он не содержит твоих сцен и игровых ресурсов.
При установке полного исходного движка с нуля смотри README.txt / build.cmd.
Готовый MyEngine2.exe в исходный архив не входит.

ГДЕ ОТКРЫТЬ
Редактор → Assets / extensions → Коммерция / генератор сайта.
То же окно открывают прежние кнопки «Донаты / транзакции» в настройках UI
и UI Blueprints. Работает с проектом, который сейчас открыт в редакторе.

БЫСТРЫЙ СТАРТ ДЛЯ ТВОЕГО MYENGINE DELUXE
1. Нажми «Мой MyEngine Deluxe · 10 ₽».
   Загрузятся твой кошелёк, контакт поддержки и сохранённая проверка
   разработчика из подготовленного сайта (ID разработчика test).
   Ни телефон, ни последние цифры карты в архиве не сохраняются.
   Для другого проекта укажи собственные реквизиты — они не подставляются
   автоматически при создании нового проекта.
2. На вкладке «Товар и контакты» проверь название, ID товара (deluxe), цену,
   кошелёк ЮMoney, контакты и порядок активации.
3. Нажми «Экспорт сайта для Render…» и выбери ZIP.
4. Распакуй сайт и загрузи его содержимое в репозиторий сайта на GitHub.
   Render → New → Static Site → выбери репозиторий.
   Build Command: node scripts/build-static.mjs
   Publish Directory: dist
   Root Directory пустой, если index.html в корне репозитория.
5. В генераторе, на вкладке «Сайт и кнопки», вставь HTTPS-адрес Render
   и нажми «Сохранить и подключить сайт к кнопкам».
6. UI Blueprints → выбери существующую кнопку → Create / edit Blueprint.
   Узел Transaction start: product = deluxe; key = deluxe_order.
   Если старая кнопка содержит product=donation, поменяй его на deluxe.
   Затем Apply to UI → Ctrl+S → Play.
   У новых графов product берётся из сохранённых коммерческих настроек.
   Для «Открыть донат» можно использовать тот же сайт: галочка включена
   по умолчанию. Другую платёжную ссылку можно оставить отдельно.

ИМПОРТ И ИЗМЕНЕНИЯ
«Импорт ZIP / config.js…» читает настройки из MyEngine-Deluxe-YooMoney.zip,
конфигурационного JS или JSON. JS не выполняется, читается только JSON.
Для смены товара или цены заново экспортируй и опубликуй сайт.
Один экспорт содержит один товар; для других товаров создавай отдельные сайты.
Экспорт сайта не публикует ничего автоматически и не совершает оплату.

КАК СВЯЗАНА ИГРА
Коммерческие настройки: .myengine/commerce.json (редактор, не сборка игры).
Адрес для игры: payments.json (входит в сборку).
checkoutMode=site: Transaction start открывает сайт с product и requestId.
Запись получает состояние manual. Её requestId входит в метку перевода
ME-<requestId>. Через Python доступен transactions.request_id(key).
ID игрока вводится на сайте; после перевода он передаётся поддержке вместе
с меткой и номером операции. В браузере хранится только локальная подсказка.
Сайт не меняет цену/кошелёк по URL. Другой product в URL блокирует оплату.
Transaction paid once и succeeded в этом режиме не выставляются.
Transaction reset разрешён для manual, но перед повторной покупкой нужно
выяснить статус предыдущего перевода — повторный платёж сам не возвращается.
checkoutMode=api сохраняет прежний серверный контракт TRANSACTIONS_R12.txt.
При подключении сайта старый checkoutApi сохраняется. Выбрать API-режим
обратно можно на вкладке «Сайт и кнопки». Не ставь URL сайта в checkoutApi.
Чтобы новые настройки вступили в силу, останови и заново запусти Play.

СЕРТИФИКАТ РАЗРАБОТЧИКА
Сохранена прежняя локальная проверка ID, последних четырёх цифр и телефона.
Вкладка «Разработчик» позволяет заменить её. После ввода нажми «Настроить
проверку», затем сохрани или экспортируй сайт. Телефон и цифры очищаются;
в настройках остаются соль и SHA-256-отпечаток.
Сертификат выдаётся бесплатно: payment.status=not_required, amount=0.
Название игры, издания и ID товара соответствуют настройкам генератора.
Это неподписанный JSON; он не подтверждает банковскую операцию.
В R15 импорт такого сертификата ещё не был добавлен. В R19 доступно окно
CertificateImport и сохранение локальной активации — см. CERTIFICATES_R19.txt.

ПРОВЕРКИ R15
30 Python-проверок: настройки, экспорт, импорт, транзакции, Blueprint и сборка.
11 JavaScript-проверок: цена, URL, метки, неверные данные и повторное нажатие.
Сборка статического сайта Node проверена. Настоящих платежей не выполнялось.
Windows-окно редактора и нативный запуск игры в этой среде не проверялись.
