2. ПРОСТАЯ ЖИДКОСТЬ
В Hierarchy появилась кнопка Liquid. В Inspector — Liquid JSON.
Нажми Play: в режиме редактирования поверхность показана неподвижно.
Проверка на готовом примере: start_liquid_demo.cmd
(или открой map-liquid-r26.json в редакторе и нажми Play).
Клавиша 1 создаёт волну, 2 добавляет 0.5 кубической единицы воды.

Это поверхностная модель неглубокой жидкости в закрытой прямоугольной
сетке. Есть волны, инерция, перетекание между ячейками, затухание,
добавление воды, высота дна и непроницаемые ячейки. Объём сохраняется;
команда splash не добавляет воду. Границы бассейна закрыты.
Это не 3D-частицы: нет брызг, переворота бассейна, автоматического
обтекания произвольных Collider и плавучести Rigidbody. Препятствия
задаются через solid, рельеф дна — через bed. В демо видимый оранжевый
блок совпадает с заданными solid-ячейками.

Рекомендуется отдельный объект, scale=(1,1,1), без поворота X/Z,
без модели, Collider/Rigidbody/VOX/4D. Положение объекта можно менять.
Поворот и масштаб меняют отображение; расчёт ведётся в локальной X/Z
сетке с локальной вертикалью Y, а объём указан в локальных единицах.

Минимальный Liquid JSON:
{"nx":32,"nz":32,"cellSize":0.25,"depth":0.6,"gravity":9.81,"damping":1.5,"updateHz":20}

nx/nz: 2..128 ячеек, по умолчанию 32x32; cellSize: сторона ячейки.
depth: начальная толщина воды над дном каждой незаблокированной ячейки.
updateHz: 10..60. bed: массив nx*nz высот дна (по умолчанию 0).
solid: массив nx*nz true/false (по умолчанию false).
Индекс: z*nx+x. Сетка центрирована относительно объекта.
Для большого масштаба начни с 32x32 и 20 Гц, затем увеличивай сетку.

Из Python Script:
    water = self.world.instantiate(
        name='Water', color=(0.06,0.35,0.8),
        liquid={'nx':32,'nz':32,'cellSize':0.25,'depth':0.6})
    water.liquid.splash(x=0,z=0,strength=3,radius=1)
    water.liquid.add_water(x=0,z=0,volume=0.1,radius=0.6)
    volume = water.liquid.volume  # последний завершённый шаг
    water.remove_liquid()

На существующем пустом объекте: entity.add_liquid(nx=32,nz=32,depth=0.6).
Не вызывай методы объекта из своих фоновых потоков: команды отправляет
обычный Script.update. LiquidSystem выполняет расчёт в пуле из двух
потоков. Нативный численный шаг FluidNative.dll освобождает GIL;
графические ресурсы обновляются только в потоке движка. Без DLL есть
медленный Python fallback. Не более 32 бассейнов в сцене. При перегрузке
время расчёта ограничено: симуляция может замедлиться, очередь не растёт.
Параметры компонента сохраняются в сценах/префабах; текущее состояние
волн автоматически в сохранение игры не записывается.
Linux: tools/build_linux_native.py теперь также собирает libFluidNative.so.

3. BLENDER <-> 4D
Отдельный архив: MyEngine_Blender_4D_1_1_0.zip (аддон 1.1.0).
В комплекте движка: addons/MyEngine_Blender_4D_R26.zip с тем же аддоном.
Исходники аддона также лежат в addons/myengine_4d.
Blender 3.1: Edit -> Preferences -> Add-ons -> Install,
выбери ZIP и включи MyEngine 4D Hierarchy.
Импорт: Object Mode -> File -> Import -> MyEngine 4D 1.1.0 (.4d).
Экспорт: выдели КОРНЕВОЙ объект -> File -> Export -> MyEngine 4D 1.1.0.
Панель N -> MyEngine содержит импорт, экспорт и Duplicate as child layer.

Пример: Root -> Child -> Grandchild:
Root: W=0; Child: W=0.1; Grandchild: W=0.2.
Два ребёнка одного родителя образуют один слой, а не два отдельных W.
Их геометрия объединяется. Родительская геометрия не дублируется во все
дочерние слои: каждый уровень содержит только объекты своей глубины.
По умолчанию корневой Empty считается контейнером: его дети имеют W=0.
Root is layer 0 позволяет считать и корневой Empty нулевым слоем.
Промежуточные Empty сохраняют глубину. Пустые слои остаются пустыми.

Шаг W по умолчанию 0.1, меняется в экспорте и записывается в .4d.
Сохрани файл в assets своего проекта; двойной щелчок по нему в Project
добавит объект и прочитает его шаг W. При создании из Python без явного
layer_spacing шаг также читается из файла. Для уже добавленного объекта
после смены шага при повторном экспорте обнови Layer spacing в Inspector.

Экспортируются треугольники, UV и нормали сглаживания, трансформации
дочерних объектов, результат модификаторов (отключаемо). Оси переводятся
Blender(X,Y,Z) -> MyEngine(X,Z,-Y). Позиция корневого pivot становится
(0,0,0); его поворот и масштаб запекаются. Отрицательный масштаб учитывается.
Текстуры и материалы назначаются в MyEngine отдельно. Скрытая геометрия
по умолчанию исключена; глубина её видимых потомков сохраняется.
Коллекционные инстансы, Geometry Nodes instances и анимация не запекаются
в отдельные W-кадры: сделай instances реальной геометрией перед экспортом.
Лимиты: 256 слоёв, 64 MiB на файл; большие модели лучше упрощать.
Экспорт пишет временный файл: при ошибке старый .4d остаётся целым.

ИСПРАВЛЕНИЕ АДДОНА 1.0.1 — 17.10.2026
Убрана обязательная зависимость от mesh.corner_normals. Экспортёр выбирает
доступный API нормалей: corner_normals или calc_normals_split/loop.normal,
затем нормали граней/вершин как запасной вариант. Вручную править меш
не требуется. Обнови ZIP аддона и перезапусти Blender. Пересборка движка
для этого исправления не нужна. Добавлены тесты отсутствующего/пустого
corner_normals, старого API, custom normals и flat/smooth fallback.

ИСПРАВЛЕНИЕ АДДОНА 1.0.2 — 17.10.2026
Полностью удалено обращение к mesh.corner_normals. Используются loop.normal
и доступный старый метод calc_normals_split, затем flat/smooth fallback.
При загрузке обновляются собственные дочерние Python-модули аддона.
Версия 1.0.2 явно видна в панели N и меню экспорта, а также в ошибках.
Отдельный ZIP: MyEngine_Blender_4D_1_0_2.zip. В комплекте движка находится
тот же аддон 1.0.2 в addons/MyEngine_Blender_4D_R26.zip.
Если в Blender не написано 1.0.2, новая версия ещё не загружена.

ИМПОРТ .4D — АДДОН 1.1.0 — 17.10.2026
Добавлен File -> Import -> MyEngine 4D 1.1.0 (.4d) и кнопка Import .4d
в N -> MyEngine. Один меш на слой, вложенность соответствует W; пустые
слои сохраняются. Восстанавливаются UV, нормали, XYZ и шаг W. Импорт

текстуры, модификаторы и исходные ветви иерархии не восстанавливаются.
Старый spherecube.4d и повторный экспорт проверены автоматическими тестами;
