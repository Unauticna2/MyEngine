MYENGINE 2.5 — BLUEPRINTS R18
15 октября 2026

НОВЫЕ УЗЛЫ
SetVisible / Set visible: visible=true показывает объект, false скрывает.
Объект сохраняет координаты, скрипты продолжают выполняться.
Коллайдер и Rigidbody остаются включёнными. Это управление отображением,
а не выдача права собственности на покупку.

SetPosition / Set position (XYZ): присваивает мировые координаты x/y/z.
Повторное выполнение с теми же числами не перемещает объект дальше.
Координата W сохраняется. Допустимый диапазон XYZ: -1000000..1000000.

Move / Move (offset): по-прежнему ДОБАВЛЯЕТ смещение при каждом выполнении.
Move(0,0,0,0) ничего не меняет, в исходную позицию объект не возвращает.
Для движения в Update подключайте speed * DeltaTime.
Для скрытия используйте SetVisible, а не огромные смещения.

ОБНОВЛЕНИЕ
Закрой редактор и игру. Распакуй MyEngine2_Blueprints_R18.zip в папку
движка, где находятся engine_blueprints.py и MyEngine2.exe, с заменой.
Архив накопительный: включает изменения Commerce R15–R17 относительно R14.
Для обновления с R14–R17 пересобирать EXE не требуется.
Проектные скрипты в этот архив не входят: исправления MyGame поставляются
отдельно в MyGame_Blueprints_R18.zip.

КАК РАБОТАЕТ УСЛОВИЕ ПОКУПКИ
Start и Update -> Branch; TransactionIs.value -> Branch.condition.
True -> SetVisible(visible=true), False -> SetVisible(visible=false).
Для постоянной видимости после покупки нужен TransactionIs(state=succeeded).
TransactionPaidOnce возвращает true только один раз, поэтому не подходит
для такой проверки видимости в каждом кадре.
Вместо Branch можно соединить TransactionIs.value прямо с SetVisible.visible.
SetVisible действует на объект, к которому прикреплён скрипт.

key в TransactionIs должен совпадать с key в TransactionStart.
product задаёт ID товара; key задаёт ключ операции в игре. Это разные поля.
Открытие статического сайта даёт manual, а не succeeded. Автоматическое
succeeded требует проверенного подтверждения от настроенного checkout API.
В R18 импорта сертификатов ещё не было. Начиная с R19 он доступен через
CertificateImport; для доступа после импорта используйте TransactionHasAccess.
Подробности в CERTIFICATES_R19.txt. Статус succeeded остаётся серверным.

ДИАГНОСТИКА ПРИСЛАННЫХ СХЕМ
Python во всех четырёх парах соответствует соединениям Blueprint.
В blurinttransction ветка false прибавляла 1000000 к Y каждый Update.
В blurinttransction2 ветка false прибавляла 100000 к Y каждый Update.
Оба варианта выходили за допустимый диапазон координат.
Неподключённые узлы не исполняются; редактор показывает их количество.
В hzchtozascript KeyDown(Y) означает спавн каждый кадр удержания Y.
Если нужен один спавн на нажатие, замените его на KeyPressed.

ПРОВЕРКА
31 тест Python: новые узлы, воспроизведение исходных сбоев, повторное
выполнение, native.visible, UI callbacks, генерация и ошибки настройки оплаты.
Обе выдаваемые схемы MyGame дополнительно прошли по 3600 Update с переходами
idle/pending/manual/succeeded/canceled/succeeded: координаты не меняются,
скрипты не отключаются, видимость соответствует статусу.
Тесты использовали Python runtime и структуры NativeEntity без Windows EXE.
Windows-редактор и нативный рендер в этой среде не запускались.
