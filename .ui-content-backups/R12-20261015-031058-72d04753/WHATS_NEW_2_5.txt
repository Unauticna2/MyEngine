MYENGINE 2.5 — ресурсы, интерфейс и PNG-сохранения

УСТАНОВКА
Распакуйте полный архив в новую папку или обновление поверх 2.4.
Пересоберите Windows-ядро через build.cmd: появились новые экспорты в EXE.
Демонстрация: start_features25.cmd. В меню нажмите PLAY; F1 сохраняет PNG,
F2 восстанавливает выбранные поля. Сохранение: ~/MyEngineSaves/save.png.
Сцена map-features25.json — самостоятельный пример. Обновление содержит только
изменённые относительно архива 2.4 файлы; map.json в обновление не включён.
Свои изменения в исходниках сохраните перед распаковкой поверх проекта.

1. ОБЩИЙ КЭШ
OBJ/4D-меши, текстуры и исходные VOX/VXL хранятся на уровне проигрывателя,
а не отдельной сцены. Повторный spawn/переход в сцену переиспользует ресурс.
Модель декодируется и загружается на GPU снова только после изменения файла,
вытеснения неиспользуемого ресурса или перезапуска процесса.
Граница кэша — один процесс, не отдельные Editor/Game окна и не запуски программы.
Ключ включает полный путь, размер и время изменения файла.
При обычной перезагрузке сцены редактирование исходника подхватится автоматически.
При изменении геометрии скриптом используйте API set_voxel / grid.set, а не запись
напрямую в pixels: pixels теперь read-only. Копии сетки отделяются при изменении.
Одинаковые экземпляры разделяют 3D-текстуру и подготовленную геометрию коллайдера.
GPU-операции выполняются только на потоке рендера. Для холодного чтения OBJ/текстур
и вокселей используется постоянный пул работников; он не создаётся каждый кадр.
Кэш CPU/мешей: ориентировочно 512 MiB; кэш воксельных текстур: 128 MiB.
Живые ресурсы не выбрасываются ради лимита; это ориентиры, а не жёсткий лимит RAM.
Лимит 32 видимых воксельных чанка сохраняется. Кэш не устраняет стоимость их рендера.

2. POWERPOINT → 2D UI
Editor → Assets / extensions → PowerPoint / 2D interface.
Import from open PowerPoint подключается к уже запущенному PowerPoint в Windows.
Откройте .pptx, выберите её окно, переключитесь в редактор и нажмите кнопку.
Выгружается активная презентация, включая несохранённые правки, через SaveCopyAs.
Изменяется и закрывается только временная копия. Оригинал остаётся открытым.
Никакие setup/pip/LibreOffice для этого импорта не требуются. См. POWERPOINT_OPEN_IMPORT.txt.
Игрок использует готовые PNG/JSON и не нуждается в PowerPoint.
Результат: assets/ui/<имя>/interface.ui.json + изображения отдельных фигур; фон слайда не импортируется.
Исходная презентация не сохраняется с изменениями.
Старые интерфейсы тоже автоматически показываются без фона слайда: фон
по умолчанию выключен в рендере. Ручное редактирование UI JSON не нужно.
Галочка Show slide background в диалоге UI включает сохранённый фон при необходимости.
Настройка хранится в сцене, действует в Edit/Play и при сборке игры.
Поддержаны основные Appear/Fade/Fly/Zoom/Spin, время, группы кликов, With/After Previous.
Fly импортируется снизу; нестандартные направления/параметры корректируйте в JSON.
Неподдержанные эффекты, пути движения, медиа и сложные триггеры не воспроизводятся
полностью: проверяйте сообщения импорта и итоговый интерфейс. GIF внутри фигуры
экспортируется как статическое изображение; для кадров используйте frames/fps.
Подключение GetActiveObject проверено пользователем. Полный экспорт нового режима
в Windows требует проверки: здесь проверены Python-обвязка и обработка ошибок.

JSON кнопки вставляется в Alternative Text (замещающий текст) фигуры:
{"myengine":{"id":"play","onClick":[{"action":"ui","enabled":false}]}}
Теперь тот же JSON можно написать целиком в тексте самой фигуры.
При экспорте этот служебный текст скрывается; фон и оформление фигуры остаются.
Для кнопки с надписью «Играть» оставьте надпись в фигуре, а JSON — в Alternative Text.
Alternative Text имеет приоритет. Исходный PPTX не изменяется.
Фигуры экспортирует открытый PowerPoint. Фон слайда пропускается. Импортер не вызывает CreateObject/New-Object
для PowerPoint и не вызывает Quit. Отдельный необязательный LibreOffice-импорт сохранён
для API в engine_pptx_libreoffice.py; редактор не требует его установки.

Другие действия в onClick / onEnter:
{"action":"next"}
{"action":"slide","slide":"2"}
{"action":"enableSlide","slide":"2","enabled":false}
{"action":"element","id":"button1","enabled":false}
{"action":"scene","path":"scenes/game.json"}
{"action":"script","object":"Cube","path":"scripts/Move.py","enabled":true}
{"action":"call","object":"Cube","method":"begin_game","args":[3]}
Script включает существующее прикрепление или добавляет скрипт. Для call метод
должен быть публичным. Доверенность проекта/объекта по-прежнему учитывается.
Отключение слайда: служебная фигура с Alternative Text:
{"myengine":{"slide":{"id":"menu","enabled":false,"modal":true}}}
Такая фигура сама не экспортируется. Скрытые слайды PowerPoint тоже disabled.

Из Python:
ui = self.world.load_ui('assets/ui/Example/interface.ui.json')
ui.show_slide('menu')
ui.set_slide_enabled('info', False)
ui.set_element_enabled('play', False, slide='menu')
ui.enabled = False
self.world.load_ui(None)  # снять интерфейс

Картинки UI задаются относительно interface.ui.json. Действия scene/script —
относительно корня проекта. Клик проверяет повёрнутую и анимированную кнопку.
modal=true блокирует штатное управление игроком, пока слайд открыт.
Настройки самописного контроллера тоже должны учитывать world.input.
В редакторе кнопки предпросмотра не выполняют действия: включите Play.

3. ПЛАТФОРМЫ — ФАКТИЧЕСКОЕ СОСТОЯНИЕ
Windows x64: прежняя сборка EXE + Data, Python находится внутри Data.
Linux x64: добавлен экспериментальный проигрыватель SDL2/OpenGL с теми же
Python-модулями, UI, вокселями, ASM-физикой и C++-ядром 4D. Экспорт в Build game.
Запуск: sh run.sh. Нужны Python 3.11–3.13, SDL2, libGL, libstdc++ и дополнительные
Python-пакеты вашего проекта. Это НЕ автономный Linux ELF со встроенным Python.
Windows-специфичные ctypes/WinAPI/DLL в ваших скриптах автоматически не переводятся.
В комплекте Linux ELF64-библиотеки, собранные в среде разработки. При несовпадении
glibc/libstdc++ пересоберите их на целевой системе:
  python3 tools/build_linux_native.py --jwasm /путь/к/jwasm
Нужны JWasm, GCC и G++; источник JWasm: https://github.com/JWasm/JWasm.
Исходная Physics.asm общая. Адаптер physics_abi.c переводит SysV ↔ Win64 ABI.
Прямой запуск из исходников:
  python3 engine_linux.py --project . --scene map-features25.json
Linux-физика и рендер проверены в реальном Mesa/EGL; SDL-окно на рабочем столе
в данной среде не проверялось.

Android / WebGL: НЕ ГОТОВЫ. Пункты явно помечены «port required» и не создают
якобы готовый APK/HTML. Нужны перенос физики на ARM64/WASM, OpenGL ES/WebGL-рендер,
хост Python, ввод и адаптация нативных библиотек. Все текущие функции движка на
этих платформах пока недоступны. Этот запрос выполнен лишь частично.

4. ШТАТНОЕ УПРАВЛЕНИЕ
Assets / extensions → Game controls / diagnostics.
В runtime сцены: diagnosticTitle, cameraReset, scriptReload, wKeys, lightKeys,
escapeQuits, freeFly, mouseLook. Все — true/false.
По умолчанию диагностический заголовок, R/F5/Q/E, свет и Escape выключены;
freeFly/mouseLook включены. В Python: world.configure_runtime(scriptReload=True).
Скрипты могут читать клавиши, даже если штатное действие отключено.
Редактор оставляет свои навигационные клавиши независимо от игровой сборки.

5. PNGJSONUnitylity — ОДИН КЛАСС ДАННЫХ
from PNGJSONUnitylity import PNGJSONUnitylity
future = PNGJSONUnitylity.ToPngJson(path, my_data)
loaded = PNGJSONUnitylity.FromPngJson(path, GameSave)

Пример класса и применения: scripts/PngSaveExample.py.
ToPngJson в игре возвращает Future. Не вызывайте future.result() с ожиданием
в update: захват производится после draw, завершение проверяйте через done().
В конце кадра читаются пиксели; PNG сжимается и атомарно записывается работником.
Захват GPU-пикселей всё равно может дать краткую задержку; это не async GPU readback.
JSON отражает момент запроса, изображение — конец текущего кадра, включая UI.
Можно передать готовые PNG bytes третьим параметром для немедленной записи.
Включаются только поля переданного dataclass / обычного объекта / JSON-значения.
FromPngJson не меняет сцену сам: применение загруженных полей определяет разработчик.
Поддерживается простой класс без аргументов конструктора либо dataclass.
Вложенные dataclass после загрузки остаются JSON-словарями; типизированная вложенная
реконструкция не выполняется. Не передавайте Entity/World/Transform вместо данных.
UTF-8 JSON записывается в стандартный PNG iTXt, CRC проверяется при чтении.
Чужой PNG без данных даёт понятную ошибку. Пересохранение картинки сторонним
редактором может удалить метаданные; храните исходный PNG сохранения.
Ограничения: JSON 8 MiB, PNG 128 MiB, четыре запроса захвата в очереди.

ПРОВЕРЕНО ПРИ ПОДГОТОВКЕ
63 unit-теста, включая реальное C++-ядро 4D; 19 runtime-тестов физики/сцен.
Код Camera.asm и Engine.asm собран MASM-совместимым JWasm без ошибок.
Реальный Mesa/OpenGL: тени между полигонами/вокселями, солнце, общий GPU-кэш,
отделение изменённых вокселей, UI и скриншот с JSON. Linux ASM-физика проверена.
Полная линковка и запуск Windows EXE через MSVC здесь не выполнялись.
Linux SDL-окно здесь не запускалось. Отдельный LibreOffice-импорт ранее проверен на Linux.
Импорт из открытого PowerPoint: 11 тестов Python-обвязки с подменой экспортера,
без реального Windows COM. Рендер средствами PowerPoint здесь не проверен.
