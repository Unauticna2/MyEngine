MyEngine 2.5 R27, build 2.5-R27-20261017.2

УСТАНОВКА
Закрой редактор и игру. Распакуй обновлённый MyEngine_Update_R27.zip
в папку движка с заменой файлов. Подходит поверх R26 и R27.
Пересборка существующего R26/R27 EXE не требуется: изменения в Python.

НОДЫ В СПИСКЕ ADD NODE
OnCollisionEnter — один раз в начале столкновения.
OnCollisionStay  — каждый шаг физики, пока контакт сохраняется.
OnCollisionExit  — один раз после прекращения контакта.
OnTriggerEnter   — один раз при входе в триггер.
OnTriggerStay    — каждый шаг физики внутри триггера.
OnTriggerExit    — один раз при выходе из триггера.

КАК ПОДКЛЮЧИТЬ
1. Добавь Collider объекту в Inspector и включи его.
2. Для проходящей насквозь зоны включи Is Trigger; используй OnTrigger*.
   Для твёрдого столкновения оба коллайдера должны быть без Is Trigger;
   хотя бы одному объекту нужен обычный, не кинематический Rigidbody.
3. В редакторе Blueprints выбери событие из списка -> Add node.
   Соедини белый выход next с входом in нужного действия.
4. Нажми Generate Python. Прикрепи полученный .py в Scripts именно
   того объекта, чей Collider должен получать события. Сохрани сцену.
5. Запусти Play. У второго объекта тоже должен быть включён Collider,
   а его слой и маска должны разрешать контакт с первым объектом.

Пример: OnTriggerEnter -> LoadScene (path: scenes/level2.json).
Отметь Player only на событии, чтобы сцену менял только игрок.
Для проверки: OnCollisionEnter -> Print (text: Столкновение).

ФИЛЬТРЫ В ПАНЕЛИ ПАРАМЕТРОВ СОБЫТИЯ
Other object name — точное имя ВТОРОГО объекта с учётом регистра.
Пустое поле принимает любое имя. Имя встроенного игрока: player.
Player only — принимает только встроенного игрока, а не произвольный
объект с похожим названием. Можно сочетать оба фильтра.
В графе допустимо несколько событий одного типа с разными фильтрами;
каждая подходящая цепочка выполняется по одному разу на событие.
DeltaTime внутри физической цепочки равен фиксированному шагу физики.
Для одного действия при касании используй Enter; Stay повторяется.

ГОТОВЫЙ ПРИМЕР
Открой scripts/physics_events.blueprint.json. Все шесть событий соединены
с Print и пишут свои названия в Console. Рядом лежит готовый .py:
достаточно прикрепить его к объекту с Collider и запустить Play.
Тип реально приходящих событий зависит от Is Trigger у контактирующей
пары. Для триггеров Rigidbody в MyEngine не обязателен.

СОВМЕСТИМОСТЬ
Старый Blueprint: добавь событие и повторно Generate Python в тот же .py.
Меняется только сгенерированный регион; ручной код сохраняется.
Ручной on_collision_enter/on_trigger_enter и соответствующий Blueprint
могут сосуществовать: сначала вызывается ручной обработчик, затем граф.
Не вызывай _bp_on_* самостоятельно из ручного обработчика, иначе он
запустится второй раз. В сгенерированной функции доступны other, dt;
для OnCollision* также collision (point, normal, penetration, impulse).
Отключённые или недоверенные скрипты не выполняют цепочки событий.
При удалении второго объекта/отключении Collider оставшийся объект
получает Exit на следующем шаге физики. Удалённый объект не получает
события сам. Edit mode не запускает игровую физику и эти события.

ПРОВЕРКА
Новые проверки выполняют реальные контакты нативной Linux-физики,
а не имитацию сигналов: Enter/Stay/Exit, игрок, Is Trigger, отключение
Collider и уничтожение. Дополнительно проверены генерация, фильтры,
перегенерация старого скрипта, hot reload, доверие и fixed DeltaTime.
Windows/MASM EXE в этой среде не запускался.
