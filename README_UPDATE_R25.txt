MyEngine 2.5 — R25
Runtime/editor build: 2.5-R25-20261016.1

УСТАНОВКА ПОВЕРХ R24
1. Закрой игру, Hub и редактор.
2. Сделай копию текущей папки движка.
3. Распакуй MyEngine_Update_R25.zip в папку движка с заменой файлов,
   рядом с MyEngine2Editor.py и engine_runtime.py. Папку tools тоже скопируй.
4. Запусти build.cmd, чтобы пересобрать MyEngine2.exe. EXE должен быть закрыт.
   Команды меню игры передаются через обработчик окна на ASM: Python
   не вызывается из чужого потока Windows. Затем запусти движок.
5. Уже экспортированные игры нужно собрать заново: в их Data лежит прежний runtime.

МЕНЮ ЗАГОЛОВКА (WINDOWS)
Правый клик именно по системному заголовку окна игры, редактора или Hub:
- Восстановить с GitHub…
- Полный экран (F11 — вернуться; поддержан фокус встроенного viewport).
- О программе / номер сборки…
- Разблокировать всё (донат добровольный).
В полном экране также доступно системное меню Alt+Space.
Галочка редактора записывает настройку открытого проекта. Галочка Hub —
настройку папки движка; она не меняет сразу все независимые проекты.

ДОНАТ — ДОБРОВОЛЬНЫЙ
В корне проекта создай/измени donation_access.json:
{
  "unlockAll": true
}
В собранной игре файл находится в Data/donation_access.json.
Можно воспользоваться галочкой в меню; JSON обновится автоматически.
Изменение файла подхватывается примерно за секунду, перезапуск не нужен.
false возвращает обычные правила доступа проекта.
Это обычная открытая настройка: защита от изменения игровых файлов не добавлялась.

Режим открывает TransactionHasAccess / has_access и прежний игровой gate
PlayerVerified / player_verified. Старые сгенерированные Python-скрипты gate
также работают. В палитре PlayerVerified теперь подписан
«Game entry (SMS or free mode)», чтобы не путать вход в игру с личностью.
Для настоящего результата SMS/серверной проверки добавлен IdentityVerified /
transactions.identity_verified(key). Серверные роли/права не меняются.
Статусы платежей, TransactionIs(succeeded) и TransactionPaidOnce не подделываются.
Если свой скрипт закрывает контент непосредственно по статусу платежа,
переведи его игровой доступ на transactions.has_access(key).
Кнопки добровольного пожертвования остаются работоспособными.

СГЛАЖИВАНИЕ OBJ
- Готовые нормали vn сохраняются и имеют приоритет.
- s on / s 1 / s 2… объединяют нормали внутри соответствующей группы.
- s off и s 0 сохраняют жёсткие грани.
- UV-швы не разрывают сглаживание общей вершины.
- Полигоны учитываются без лишнего веса вершины, от которой строится веер треугольников.
- Работает и для OBJ-слоёв .4d; коллизии и геометрия не изменяются.
После установки перезапусти viewport, чтобы старые меши вышли из кэша.
Модель с s off и отдельными плоскими vn намеренно останется гранёной:
это её заданная автором настройка. Автоматическая сварка вершин не выполняется.

СБОРКА И ПУБЛИКАЦИЯ
Build game → вкладка «GitHub / версии»:
1. Введи версию игры и существующий репозиторий в виде автор/репозиторий.
2. Установи GitHub CLI (кнопка в окне) и войди в аккаунт (кнопка «Войти»).
3. Поставь «Разрешаю публиковать готовую игру после каждой сборки».
4. Собери игру. Разрешение запоминается в release-settings.json проекта.
Публикуется ZIP всей готовой папки игры, а не исходный проект.
Для каждого билда создаётся build.json с версией, уникальным ID, датой UTC,
ревизией движка, платформой, репозиторием, точным тегом и именем ZIP.
По умолчанию сборки попадают в отдельные подпапки Builds, старые не заменяются.
Существующий опубликованный тег не перезаписывается.

Если загрузка не удалась, готовая игра остаётся на диске. Кнопка
«Повторить публикацию» продолжает тот же билд без пересборки. Она может
завершить принадлежащий этому билду черновик релиза; чужой релиз не заменяет.
Если ответ потерялся после успешной публикации, повтор определит уже
опубликованный релиз по его метаданным. Проверки целостности установки нет.
Снятие галочки отключает публикацию следующих сборок.
Не храни GitHub-токен в проекте: используется авторизация установленного gh.

ВОССТАНОВЛЕНИЕ
Правый клик по заголовку → «Восстановить с GitHub…».
В собранной игре уже подставлены её репозиторий, точный тег и ZIP.
«Получить список версий» показывает до 100 последних публичных релизов;
для более старого релиза можно ввести точный тег и имя ZIP вручную.
Для движка репозиторий пока не задан: укажи свой репозиторий и ZIP-релиз,
при желании поставь «Запомнить». Ссылка сохранится в engine-release.json.
Обновление не создаёт выдуманный репозиторий и само не публикует исходники движка.

Скачивание и распаковка идут в отдельном потоке. Восстановленная версия
появляется в НОВОЙ папке (по умолчанию Downloads/MyEngineRestored).
По завершении открывается эта папка: запусти EXE оттуда.
Текущая работающая установка и её файлы не перезаписываются. Сохранения,
лежащие прямо в старой папке игры, автоматически в новую не переносятся.
Проверяется только корректность путей скачанного ZIP и полнота загрузки,
никакого сравнения/хеширования установленных файлов при запуске нет.
Встроенное восстановление работает с публичными GitHub Releases;
приватные сборки скачивай через авторизованный GitHub / gh отдельно.
Git для восстановления не нужен. Нужны интернет и штатный Windows PowerShell.

ПРОВЕРЕНО
97 автоматических проверок: OBJ/4D, свободный доступ и прежние сертификаты,
Blueprint, упаковка сборки, opt-in публикация, продолжение черновика,
точный тег восстановления, безопасные пути ZIP, IPC редактора.
Проверки упаковки используют искусственный PE-файл; это не запуск Windows EXE.
Win32-меню проверено на API-макете (ABI, команды, fullscreen/restore),
а не на настоящем рабочем столе Windows. Новая ASM-сборка, PowerShell-окно и реальная публикация
на GitHub здесь не запускались. Нужна проверка на твоём ПК.
