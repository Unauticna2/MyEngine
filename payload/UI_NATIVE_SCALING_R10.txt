MyEngine 2.5 — UI TOOLS R10
Масштаб UI + C++ библиотека обработки изображений

УСТАНОВКА ОБНОВЛЕНИЯ
1. Закрой MyEngine Editor, Hub и Viewport/игру.
2. Полностью распакуй MyEngine2_UINative_R10.zip.
3. Запусти INSTALL_UI_NATIVE_R10.cmd и выбери папку движка:
   F:\Users\User\Desktop\MyEngine
4. Запусти start_editor.cmd из этой папки.
Пересборка MyEngine2.exe не требуется. Все исправления R4–R9 включены.
Установщик ставит готовую MyEngineUI.dll x64 вместе с Python-подключением.
Резервные копии заменённых файлов: .ui-native-backups в папке движка.

МАСШТАБ БЕЗ ЧЁРНЫХ ПОЛОС
Останови Play. Открой PowerPoint / 2D interface (UI TOOLS R10).
Нажми «Масштаб UI — ширина / высота / без полос…».
Выбери режим и нажми «Применить», затем сохрани сцену.

Растянуть по ширине и высоте: заполняет всё окно и сохраняет весь слайд;
при другом соотношении сторон формы могут растянуться.
Заполнить окно: сохраняет пропорции и убирает полосы, обрезая края слайда.
Вписать целиком: прежнее поведение, возможны полосы.
По ширине / По высоте: единый масштаб по выбранной оси.
Баланс ширины и высоты: ползунок 0 = ширина, 1 = высота,
0.5 = геометрическое среднее масштабов. Этот режим сам по себе не гарантирует
отсутствие полос; для этого выбирай «Растянуть» или «Заполнить».
Выбор хранится в сцене (uiScale) и сохраняется при обновлении PowerPoint.
Старые сцены сохраняют режим «Вписать», пока ты не выберешь другой.
Отрисовка, обрезка, поворот кнопок и определение нажатий используют один масштаб.

ЧТО УСКОРЕНО
Раньше первый показ изображения выполнял PNG-фильтры, перевод в RGBA
и масштабирование текстуры попиксельными циклами Python в кадре рендера.
В R10 PNG-фильтры/цвет/альфа и масштабирование выполняет MyEngineUI.cpp.
Проверка PNG-структуры и CRC и распаковка zlib остаются в загрузчике.
Декодирование UI идёт в пуле до 4 фоновых задач; вызов C++ освобождает GIL.
OpenGL вызывается только в основном потоке: не больше одной новой текстуры
за проход подготовки. Завершённые текстуры переиспользуются из кеша.
Следующий/предыдущий слайды подготавливаются заранее.
Если нужные картинки ещё не готовы, старый слайд остаётся видимым;
тонкая полоска внизу показывает загрузку, окно продолжает отрисовываться.
Переход/анимация нового слайда начинается после готовности его картинок.
Ошибка изображения пишется один раз в консоль и не оставляет вечную загрузку.

ЗАМЕР
На предоставленном PNG 1920x1080, с приведением к текстуре 2048x2048:
прежний Python путь — 3.38 секунды; C++ путь — 0.080 секунды, примерно 42 раза.
RGBA результат совпал побайтно. Это один замер на Linux-машине проверки,
не обещание такого же ускорения всей игры на любом ПК.
Тяжёлые Python-скрипты, загрузка геометрии при смене сцены и работа драйвера GPU
не становятся асинхронными от этой DLL и всё ещё могут задерживать кадр.

БИБЛИОТЕКА
MyEngineUI.cpp, MyEngineUI.h — исходники C++17, ABI 1, без сторонних заголовков.
MyEngineUI.dll — готовая Windows x64 библиотека; требует только системные DLL.
engine_ui_native.py — ctypes.CDLL-подключение, без пакетов pip.
build_ui_native.cmd — пересборка только DLL через Visual Studio 2022 C++/SDK.
Полная build.cmd также собирает DLL. MyEngine2.exe менять не требуется.
В сборке игры библиотека автоматически копируется в Data/MyEngineUI.dll,
если разработчик явно не исключил её в настройках сборки.
При отсутствии/ошибке DLL загрузчик использует прежний Python вариант;
в окне масштаба показан выбранный обработчик (C++ либо Python fallback).

Для отдельного C++ проекта: подключи MyEngineUI.h, собери MyEngineUI.cpp
или загрузи DLL через LoadLibraryW / GetProcAddress. Экспортированы:
MEUI_Version() -> 1
MEUI_PngPixels(...) -> фильтры распакованных PNG scanlines в RGBA8 снизу вверх
MEUI_ResizeRGBA(...) -> nearest-neighbor масштабирование RGBA8
Буферы принадлежат вызывающему коду; длины проверяются; указатели не сохраняются.
Поддержка PNG как в текущем движке: 8 бит, без interlace, gray/RGB/palette/GA/RGBA.
Потоки могут вызывать функции одновременно с разными выходными буферами.
Linux: platforms/linux/libMyEngineUI.so; сборка tools/build_linux_native.py.

ПРОВЕРКА
Проверены все 5 PNG-фильтров, цветовые режимы, прозрачность, ориентация,
совпадение с Pillow и старым декодером, параллельные вызовы, некорректные длины,
ограничение фоновых задач, отсутствие ожидания в кадре, кеш, масштаб и нажатия.
Проверен реальный OpenGL рендер, включая переключение фона R9 и замену текстуры.
Windows DLL собрана кросс-компилятором; проверены архитектура, экспорты и импорты.
Windows DLL и GUI на Windows здесь не запускались. C++ ядро выполнено на Linux.
