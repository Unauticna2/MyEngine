1. LIGHT — ОБЪЕКТ В HIERARCHY
Hierarchy -> ПКМ -> Create -> Light: Directional, Point, Spot. Можно также добавить
компонент Light существующему объекту через Inspector -> Light component.
Положение двигает Point/Spot; Rotation задаёт направление локальной +Z
для Directional и Spot. Масштаб модели не меняет дальность источника.
Inspector: Enabled, Type, Color mode, Intensity, Range, Inner/Outer angle.
Нажми Apply changes, затем Ctrl+S для сохранения сцены.

Цвета:
- rgb: линейные R/G/B, допустимы отрицательные числа и значения больше 1;
- hsv: H в градусах, S от 0 до 1, V от 0 и выше;
- temperature: приближённый цвет от 1000 до 40000 K.
Отрицательная интенсивность вычитает свет. Сумма цветов рассчитывается
со знаком; ограничение цвета происходит при выводе в обычный framebuffer.
Отрицательный RGB-канал вычитает соответствующую составляющую цвета.
Дальность Point/Spot плавно ослабляет свет; Spot имеет мягкую границу конуса.

Свет действует на полигоны, текущие .4d-срезы, жидкость и воксели.
До 16 одновременно учитываемых источников: сначала Directional,
затем ближайшие к камере Point/Spot. Источников в сцене может быть больше.
Тени от одного основного Directional поддерживаются для непрозрачных
полигонов/вокселей. Point/Spot пока освещают без собственных карт теней.
Прозрачные объекты принимают направленные тени, но не отбрасывают их.

Assets / extensions -> Shadows / sun texture -> Ambient / legacy sun:
ambient — окружающий RGB; auto — старое солнце, только если нет Light;
on — старое солнце вместе с компонентами; off — только Light + ambient.
Выключение всех Light при auto не возвращает старое солнце.
Текстура солнца направляется по основному Directional, если он выбран
источником теней. Сцены, префабы и PNG сохраняют Light-компоненты.

Python:
    lamp = self.world.instantiate(name='Lamp', position=(0,3,0),
        light={'type':'point','color':[1,.2,.1],'intensity':2,'range':8})
    lamp.light['intensity'] = -1
    lamp.rotation = (90,0,0)
    lamp.add_light('spot', range=12, innerAngle=20, outerAngle=45)
Ноды Light enabled и Light intensity работают с текущим объектом.

2. ПРОЗРАЧНОСТЬ
Inspector -> Material / transparency:
Render mode = opaque / cutout / transparent. Opacity = 0..1.
Для обычного стекла/воды выбери transparent и, например, Opacity 0.4.
PNG-альфа текстуры умножается на Opacity. Two sided включает две стороны.
Cutout использует Alpha cutoff и сохраняет обычную запись глубины.

Полигоны и жидкость смешиваются после непрозрачной геометрии, с проверкой
глубины и без записи прозрачной поверхности в depth buffer. Прозрачные
объекты сортируются от дальних к ближним; для двухстороннего меша сначала
рисуются задние, затем передние грани. Отражения учитывают этот проход.
Пересекающиеся прозрачные меши могут требовать разбиения: сортировка
выполняется по объектам. Преломление лучей стеклом здесь не реализовано.

Для вокселей transparent включает объёмный проход: луч проходит через
ячейки и накапливает цвет/прозрачность по их толщине. Учитываются альфа
RGBA, Opacity и Voxel volume density. Более плотный/толстый объём темнее.
Непрозрачная геометрия внутри или за объёмом ограничивает длину луча;
камера может находиться внутри объёма. Дрожание от времени не добавляется.
Для физического стеклянного воксельного объекта оставляй альфу ячеек 255,
а прозрачность задавай материалом; существующие voxel-collider используют
свой порог заполненности. Прозрачность сама по себе не отключает Collider.
Новые Liquid-объекты редактор создаёт с transparent / opacity 0.55.

Python:
    self.entity.set_material(mode='transparent', opacity=.4)
    self.entity.set_material(mode='transparent', opacity=.1, voxelDensity=.6)
Нода Material opacity также включает transparent для текущего объекта.

3. СОХРАНЕНИЕ МИРА В PNG ЧЕРЕЗ НОДЫ
Save world to PNG: path='saves/slot1.png', key='save'.
Load world from PNG: тот же путь и ключ.
PNG state -> Branch: idle / saving / saved / loading / loaded / error.
Next у Save/Load означает, что запрос отправлен; завершение проверяется
через PNG state. Повторный запрос с занятым ключом не ставится в очередь.
В UI Blueprints для кнопок PowerPoint появились шаблоны
«Сохранить мир в PNG» и «Загрузить мир из PNG».

PNG остаётся обычной картинкой со скриншотом и JSON в iTXt-чанке.
Сохраняются:
- XYZ/W игрока, yaw/pitch, режим управления и физики, скорости;
- текущий набор объектов, включая созданные в Play и отсутствие удалённых;
- имена, позиции, повороты XYZ/4D, масштабы XYZ/W, шаг слоёв;
- модели/текстуры/скрипты по относительным путям, видимость и активность;
- Collider/Rigidbody, их параметры и скорости, Light и материалы;
- текущее содержимое воксельных сеток, включая изменения через set_voxel;
- настройки объектов жидкости, глобальный свет, тени и отражения.
Модели, изображения и Python-код PNG не упаковывает: они остаются в проекте.
Текущие волны/потоки жидкости не сохраняются — её поверхность создаётся
заново из сохранённых настроек. Интерфейс запускается из настроек сцены.

Скриншот берётся в конце кадра в GL-потоке. JSON/сжатие/запись и чтение PNG
выполняются рабочим потоком; ресурсы и смена мира — в потоке движка.
Новая сцена подготавливается перед заменой старой. Повреждённый PNG,
неправильные данные или отсутствующие ресурсы оставляют текущий мир живым.
До 8 MiB JSON, 256 MiB распакованных воксельных данных; лимит мира 4096
объектов. Запись PNG атомарная. Пути сохранений находятся внутри проекта.

Python:
    self.world.save_game_png('saves/slot1.png', key='slot')
    self.world.load_game_png('saves/slot1.png', key='slot')
    status = self.world.saves.state('slot')
    error = self.world.saves.error('slot')
Старые PNGJSONUnitylity.ToPngJson / FromPngJson для произвольного класса
сохранили прежний API.

ПОЛЯ PYTHON-СКРИПТОВ
Произвольная память Python автоматически не сериализуется. Для своих
счётчиков/инвентаря/квестов добавь методы:
    def save_state(self):
        return {'counter': self.counter}
    def load_state(self, data):
        self.counter = data['counter']
    def on_restore(self):
        self.target = self.world.find('Target')
При загрузке сохраняются скрипты и их enabled, восстанавливаются данные
через load_state, затем вызывается on_restore. Start повторно не вызывается,
чтобы он не заспавнил уже сохранённые объекты второй раз. Восстановление
нужных ссылок из Start перенеси в on_restore или общий метод. __init__
Script вызывается без аргументов; entity/world назначаются после него.

ПРОВЕРЕНО
Реальная компиляция/линковка GLSL и отрисовка в Mesa OpenGL 4.5 compatibility
через EGL: Point/Spot, отрицательный свет, альфа полигонов, объём вокселей,
отсечение по непрозрачной глубине, камера внутри объёма, Directional shadows,
reflection capture, прозрачная жидкость. PNG roundtrip выполнен настоящим
World с Linux-ядром физики, включая спавн, скорости и изменённые воксели.
Демонстрационная сцена также отрисована. Windows/MASM EXE и интерфейс
Tk на Windows непосредственно здесь не запускались.
