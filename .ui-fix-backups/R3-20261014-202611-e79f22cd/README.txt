================================================================

БЫСТРЫЙ ЗАПУСК
1. Закрой редактор. Распакуй MyEngine2_5_update.zip поверх прежней папки
   с заменой файлов. Или распакуй полный MyEngine2_5.zip в новую папку.
2. Нужны Windows x64, VS 2022 Community с Desktop development with C++,
   Windows SDK и обычный CPython 3.11–3.13 x64 с Tcl/Tk.
   Если Python ещё не настроен — запусти setup_python.cmd.
3. ОБЯЗАТЕЛЬНО запусти build.cmd: в 2.5 изменён интерфейс рендера EXE
   и собирается Slice4D.dll. Старый EXE не подходит к новому Python-коду.
   build.cmd поддерживает x64 Native Tools Command Prompt и поиск MSVC/SDK
   напрямую без vswhere. Игровому рантайму сторонние pip-пакеты не нужны.
   Импорт из открытого PowerPoint: POWERPOINT_OPEN_IMPORT.txt.
   LibreOffice и дополнительные pip-пакеты для этого режима не нужны.
4. Запусти start_hub.cmd. New project создаёт отдельную папку проекта.
5. Прежний запуск: start_editor.cmd. Он открывает map-vox.json.
   Другая сцена: start_editor.cmd map-vox-physics.json
Архив содержит исходники. MyEngine2.exe создаётся на твоём Windows.

ХАБ
New project: имя, папка, шаблон Basic 3D / VOX + 4D demo / Empty.
Add project: добавить папку. Для старого проекта без настроек хаб предложит
выбрать стартовую сцену и создаст project.myengine.json.
Open Editor / двойной клик: открыть проект. Build game: экспортировать игру.
Remove from list убирает запись из списка, файлы остаются на диске.
Список проектов: %LOCALAPPDATA%/MyEngine2Hub/projects.json.
Хаб использует эту версию движка, без загрузчика других версий.
Новый проект: project.myengine.json, scenes/main.json, assets, scripts,
textures. Движок и редактор находятся отдельно от проекта.
Пути в сценах считаются от корня ПРОЕКТА, не от папки scenes.
Пример: assets/Cube.obj, scripts/spin.py. Import file копирует выбранный файл.

РЕДАКТОР
Hierarchy выбирает объект. Inspector меняет поля кнопкой Apply changes.
Ctrl+S сохраняет сцену; Ctrl+Z / Ctrl+Y — Undo / Redo.
Move / Rotate / Scale: зажми ЛКМ на оси/кольце и тяни.
X — красная, Y — зелёная, Z — синяя. Move использует мировые оси;
Scale — повёрнутые оси объекта. Ctrl: шаг 0.1 или 15°.
У .4d фиолетовая ручка меняет W-позицию или W-масштаб.
4D rotate: внутреннее красное кольцо — XW, среднее зелёное — YW,
внешнее синее — ZW. Inspector позволяет ввести эти углы числом.
Play включает физику и скрипты. Stop возвращает документ до симуляции.
Редактирование и сборка доступны после Stop.
Камера: WASD, Space/Ctrl вверх/вниз, Shift ускорение, ПКМ — обзор.
В редакторе или при включённых соответствующих runtime-настройках:
Q/E перемещают камеру по W. R сбрасывает камеру.
Свет: F1/F2 вокруг Y, F3/F4 вокруг X, F6/F7 вокруг Z.
F5 перезагружает скрипты, если включён scriptReload. Esc закрывает viewport
в редакторе; в игре для выхода требуется runtime.escapeQuits=true.
В 2.5 диагностические клавиши по умолчанию выключены; см. WHATS_NEW_2_5.txt.
В Edit камера свободно летает сквозь объекты — это навигация редактора.

ИСПРАВЛЕНИЕ .4d
Формат: последовательность OBJ-слоёв, разделённых строкой +.
Центры по W: i * layerSpacing, по умолчанию шаг 0.1.
positions.w — перенос; scales.w — масштаб; rotations4D.xw/yw/zw — углы.
Без 4D-поворота используется исходный слой. При повороте каждый слой задаёт
объём на своём W-интервале и пересекается с W камеры.
В 2.1 были только боковые поверхности. В 2.2 добавлены грани границ W.
На стыке слоёв строятся только неперекрывающиеся части: перегородки внутри
общего объёма нет. Поддержаны вогнутые контуры, отдельные области и отверстия.
Для определения внутренности сами OBJ-слои должны быть замкнуты и не иметь
самопересечений. Открытая плоскость OBJ не задаёт твёрдое тело.
Между слоями нет автоматического плавного морфинга: модель ступенчатая по W.
Физика взаимодействует с текущим 3D-срезом, а не полноценным 4D-телом.
Срез кэшируется. В 2.5 Slice4D.dll считает его в рабочем потоке без GIL;
рендер продолжает показывать предыдущее готовое сечение. Данные физики
и GL-меш обновляются вместе в потоке движка. Сложные сечения могут отставать
от движения камеры; до первого результата объект может не отображаться.

ВОКСЕЛИ
Двойной клик по .vox в Project создаёт VoxelRenderer.
Поддерживаются палитра и статическая иерархия MagicaVoxel. По умолчанию клетка
равна 0.1, сетка центрирована, Z-up переводится в Y-up.
Настройки: "voxels":[{"path":"assets/vox.vox","cellSize":0.1}].
modelIndex выбирает модель многообъектного VOX. Без него видимая иерархия
объединяется. Для анимации используется первый кадр.
Стекло/PBR/эмиссия MagicaVoxel не воспроизводятся: используются цвета палитры
и непрозрачные клетки. Alpha < 128 означает пустоту.
Данные .vxl.json подробно описаны в legacy/README-2.1.txt.

ФИЗИКА ВОКСЕЛЕЙ
Выбери воксельный объект. В Inspector:
• + Voxel → Apply changes: точная статическая поверхность с пустотами.
  Можно ходить по клеткам, падать в отверстия. Rigidbody для неподвижного
  ландшафта не нужен. JSON: {"type":"voxel"}.
• + Box и + Rigidbody → Apply changes: падающий/двигающийся предмет.
  Box автоматически берёт размер сетки и учитывает Scale объекта.
  Он заполняет весь ограничивающий параллелепипед, включая пустоты.
• Для скриптового движения точной поверхности добавь Rigidbody
  с {"mass":1,"isKinematic":true}. Динамическая вогнутая поверхность
  не поддерживается: для свободного падения используй Box Collider.
Collider поддерживает friction, restitution, enabled, layer, mask и wSize.
Поверхность перестраивается после изменения клеток и кэшируется. Пустая
сетка не сталкивается. Частое изменение большой сетки дорого: меняй пачками.
Рендер остаётся GPU-реймарчингом. Треугольная поверхность строится только
для физики и обрабатывается native BVH/ASM-ядром.

ДЕМО ФИЗИКИ
start_vox_physics.cmd — запустить как игру.
Или start_editor.cmd map-vox-physics.json → Play.
В сцене: твой статический .vox, падающий воксельный предмет, пол,
.4d с MeshCollider и физический игрок.
Игрок: WASD, Shift, Space — прыжок, ПКМ — обзор.
scripts/player_walk.py можно прикрепить к пустому объекту своей сцены.
Он включает Rigidbody камеры только в Play. Свободная камера сама по себе
не становится физическим персонажем после добавления коллайдера ландшафту.

PYTHON API
ground = self.world.instantiate("assets/vox.vox", collider={"type":"voxel"})
item = self.world.instantiate("assets/vox.vox", position=(0,5,0),
    collider={"type":"box"}, rigidbody={"mass":2,"freezeRotation":True})
ground.add_voxel_collider()
ground.set_voxel(10,10,10,(0,0,0,0))  # удалить клетку и обновить коллайдер
four = self.world.instantiate("assets/spherecube.4d", rotation4=(20,0,0))
four.rotation4.x += 15 * dt         # угол XW
four.w += 0.1
world/entity, скрипты Behaviour, триггеры и смена сцен сохранены.
Прежняя физика: legacy/README-physics-v3.txt.
Изменения ECS/OpenGL выполняются в потоке движка. Worker-потоки читают
ассеты/строят геометрию, UI работает отдельно. Python-код ограничен GIL.

СБОРКА ИГРЫ: ОДИН EXE + ОДНА ПАПКА
1. В редакторе Stop → Save → Build game. Или Build game в хабе.
2. Выбери имя EXE, стартовую сцену и папку вывода.
3. Build создаст новую папку, например:
   Builds/MyGame/MyGame.exe
   Builds/MyGame/Data/
В корне игры ровно один EXE и Data. В Data находятся сцены, модели, текстуры,
скрипты, шейдеры и приватный Python со стандартной библиотекой.
Игроку не нужны Visual Studio, установленный Python или setup_python.cmd.
Распространяй оба элемента вместе. Игру можно перенести на другой путь:
python.ini внутри Data использует относительные пути.
Экспортёр берёт обычную x64-установку Python, в которой работает редактор.
Include installed site-packages нужен для сторонних Python-пакетов:
он копирует всю папку site-packages этой установки.
Внешние DLL/программы, которых нет в проекте и Python-пакетах, автоматически
не собираются. Tk/редактор в игру не включены. Скрипты .py остаются читаемыми.
Ассеты и сцены должны быть внутри проекта; абсолютные пути к ним отклоняются.
Внутри проекта экспорт разрешён под Builds; можно выбрать внешнюю папку.
Существующая сборка не перезаписывается — выбери новое имя или папку.

Командная строка из папки движка:
python engine_build.py --project "D:/Projects/MyGame" --output "D:/Games" --name MyGame --scene scenes/main.json

ОГРАНИЧЕНИЯ И ПРОВЕРКИ
До 4096 сущностей. До 32 видимых плотных воксельных сеток, до 256³ каждая.
Максимальная RGBA8-сетка занимает 64 МиБ до копий CPU/GPU. Это не бесконечный
разреженный мир. Большие/часто меняющиеся коллайдеры требуют времени.
Нужен OpenGL 2.1+. Изнутри вещества луч рисует поверхность выхода с правильной
глубиной. Полигональные и воксельные объекты используют общий depth buffer.
Проверено:
• 32 переносимых теста: импорт VOX, оси, замкнутость 4D-срезов,
  отсутствие внутренних граней, проекты и структура переносимой сборки.
• 7 прежних и 6 новых тестов настоящего ASM-ядра физики через Win64 ABI.
• OpenGL/Mesa: пропавшая грань воспроизведена в 2.1 и закрыта в 2.2;
  глубина вокселей изнутри/снаружи, смешивание с полигонами.
• Edit/Play/Stop, загрузка отдельного проекта, физический игрок.
• Изменённые ASM-модули собираются MASM-совместимым JWasm под Win64.
Переносимые тесты: python -m unittest discover -s tests -v
Windows EXE, Tk/Win32, resource compiler и экспортированная игра без
системного Python здесь не запускались. Тест структуры сборки использует
искусственные PE-файлы и не заменяет запуск на Windows. После build.cmd
проверь демо и экспорт своей игры.
