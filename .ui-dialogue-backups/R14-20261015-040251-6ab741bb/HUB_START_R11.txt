MyEngine 2.5 — HUB START R11

УСТАНОВКА
1. Закрой Editor, Hub и Viewport/игру.
2. Полностью распакуй MyEngine2_HubStart_R11.zip.
3. Запусти INSTALL_HUB_START_R11.cmd.
4. Выбери папку движка с MyEngine2Editor.py и MyEngine2.exe:
   F:\Users\User\Desktop\MyEngine
5. Запусти MyEngine2.exe двойным щелчком. Откроется MyEngine Hub.
Пересборка EXE не нужна: существующий EXE загружает обновлённый Python runtime.
Обновление включает R4–R10; масштаб UI и C++ ускорение остаются на месте.
Резервные копии заменённых файлов: .hub-start-backups в папке движка.

ПОВЕДЕНИЕ ЗАПУСКА
MyEngine2.exe без аргументов в папке движка: открыть Hub.
MyEngine2.exe --hub: явно открыть Hub.
MyEngine2.exe map.json: явно запустить прежнюю демонстрационную сцену.
MyEngine2.exe map-vox.json: запустить указанную демонстрацию.
MyEngine2.exe --project "Путь к проекту": запустить mainScene из project.myengine.json.
Запуск из редактора с preview.json / --editor: открыть Viewport выбранного проекта.
Собранная игра с Data/build.json: запустить mainScene из build.json, без Hub.
Для собранной игры Hub и редактор не требуются.

В папке движка больше не загружается map.json автоматически.
Сама демонстрационная сцена и ассеты не удаляются.
Стартовая сцена проекта берётся из его настроек, а не из папки движка.

Hub работает отдельным процессом Python с обычным Tk в своём главном потоке.
Используется Python Home из существующего python.ini, предпочтительно pythonw.exe.
Повторного запуска MyEngine2.exe как Python-интерпретатора нет.
Движок ждёт подтверждения открытия окна Hub без блокирующего ожидания в кадре.
После подтверждения служебное окно EXE закрывается, Hub продолжает работать.
На старом EXE до передачи запуска может кратко появиться нативное окно.
Если нужно совсем убрать это первоначальное окно и запуск OpenGL,
потребуется отдельное изменение нативной точки входа и пересборка EXE.

При ошибке запуска Hub диагностический лог находится в:
%LOCALAPPDATA%\MyEngine2\Hub\launch-*.log
Нужен обычный Python 3.11–3.13 x64 с Tcl/Tk, как для существующего Hub.
start_hub.cmd и start_editor.cmd продолжают работать.

ПРОВЕРЕНО
Выбор Hub, явной сцены, mainScene проекта/сборки и режима редактора;
передача путей с пробелами и кириллицей; ожидание ready без загрузки мира;
ошибка/таймаут дочернего процесса; реальный запуск дочернего Python с подтверждением.
Тесты выполнялись на Linux. Окна Windows/EXE здесь не запускались.
