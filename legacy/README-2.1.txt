MyEngine 2.1 — MagicaVoxel, оси редактора и преобразования 4D
=====================================================

Это обновление твоего Windows x64 движка. Native окно, камера, полигональный
рендер и ядро физики остаются на MASM x64. Редактор написан на Python/Tk,
воксельный проход выполняется на GPU в GLSL. Иконка — твой MyEngineN2.ico:
она встроена в EXE через ресурс 101 и используется в окне редактора.

НОВОЕ В 2.1
• Загрузка .vox MagicaVoxel: палитра, несколько моделей и статическая иерархия.
• Оси Move / Rotate / Scale прямо в сцене. 4D rotate — плоскости XW / YW / ZW.
• W-позиция и W-масштаб .4d, пересечение повёрнутых слоёв текущим W камеры.
• Исправлен рендер изнутри заполненного вокселя: рисуется поверхность выхода
  луча с правильной глубиной вместо поверхности у ближней плоскости камеры.
• Твой vox.vox включён в assets и стартовую сцену map-vox.json.

БЫСТРЫЙ ЗАПУСК
1. Распакуй полный MyEngine2_1.zip в отдельную папку. Если используешь
   MyEngine2_1_update.zip, закрой редактор и распакуй архив поверх прежнего движка
   и его assets / textures с заменой файлов. Обновление содержит все новые
   исходники и новые ассеты; прежние большие модели и текстуры в нём отсутствуют.
2. Нужны Windows x64, VS 2022 Community с Desktop development with C++ и
   Windows SDK, обычный CPython 3.11–3.13 x64. Для редактора включи компонент
   tcl/tk and IDLE в установщике Python. Сторонние pip-пакеты не нужны.
3. Запусти setup_python.cmd. Он запишет пути именно твоей установки Python.
4. Запусти build.cmd. Будут скомпилированы MASM-модули и ресурс иконки.
   Результат: MyEngine2.exe. Старый AsmMapEngine.exe не запускай для новой версии.
5. Запусти start_editor.cmd. По умолчанию откроется map-vox.json.
   Другую сцену: start_editor.cmd map.json
6. Без редактора: MyEngine2.exe map.json или start_vox_demo.cmd.
   Предыдущее воксельное демо: start_voxel_demo.cmd.
   Старая демонстрация физики: start_physics_demo.cmd.

В архиве исходники, а не готовый EXE: Windows-сборку нужно сделать build.cmd.
Не переноси старые .obj / .exe / .lib из build прежней версии в новую сборку.
Если ml64/link уже настроены в x64 Native Tools Command Prompt, build.cmd
использует их. Иначе ищет VS 2022 Community и SDK самостоятельно, без vswhere.
Resource compiler rc.exe поставляется вместе с Windows SDK.
Если MyEngine2.exe уже собран из версии 2.0 с редактором и voxel-проходом,
для этого обновления повторная сборка не обязательна: native ABI не изменён.

РЕДАКТОР
• Hierarchy: список объектов сцены. Выбор объекта открывает Inspector,
  а в сцене отображается оранжевая рамка его локальных границ.
• Cube / Voxel / Empty: добавить объект. Duplicate / Delete: копия / удаление.
• Inspector: имя, Active, Visible, Position, Rotation, Scale, Color, W,
  Scale W, повороты XW/YW/ZW, расстояние между 4D-слоями, модель, текстура,
  воксельный файл и скрипты.
  Нажми Apply changes, чтобы отправить введённые значения в движок.
  Ошибки живого применения выводятся в Console; предыдущий объект сохраняется.
• Collider и Rigidbody доступны в виде редактируемых JSON-полей.
  Кнопки + Box и + Rigidbody вставляют базовые настройки; затем нажми Apply.
  Можно изменить isTrigger, массу, гравитацию, трение, отскок, кинематику и т.д.
• Project: дерево файлов проекта. Двойной клик по сцене открывает её, по .obj,
  .4d, .vox или .vxl.json создаёт объект; по .py добавляет скрипт выбранному объекту,
  по PNG/BMP назначает текстуру. Import file копирует файл в assets или scripts.
  Refresh обновляет дерево после изменений внешним редактором.
• Save / Ctrl+S: сохранить сцену. Save As: сохранить под другим именем.
  Сохранение атомарное через временный файл. Неизвестные поля JSON сохраняются.
• Undo / Ctrl+Z и Redo / Ctrl+Y работают для изменений документа сцены.
• Play: запускает физику и Python-скрипты. Stop загружает состояние документа
  до Play; изменения симуляции не записываются в исходную сцену.
  Во время Play редактирование документа отключено.
• Restart viewport: заново запускает только процесс этой сцены в редакторе.
• Console отображает сообщения редактора и engine.log.

ОСИ В СЦЕНЕ
Выбери объект в Hierarchy, затем Move, Rotate или Scale над viewport.
Зажми ЛКМ на оси/кольце и тяни. X — красная, Y — зелёная, Z — синяя.
Move работает в мировых XYZ, Scale — вдоль повёрнутых осей объекта.
У .4d в Move/Scale есть фиолетовая диагональная ручка W: это экранный
регулятор четвёртой координаты, а не дополнительная пространственная ось XYZ.
В режиме 4D rotate три экранных кольца: внутреннее красное XW,
среднее зелёное YW, внешнее синее ZW. Обычный Rotate меняет повороты XYZ.
Ctrl при перетаскивании: шаг 0.1 для позиции/масштаба, 15° для углов.
Отпускание ЛКМ фиксирует одно изменение для Undo. Ctrl+S сохраняет результат.
Оси работают в Edit; во время Play объектами управляют скрипты и физика.

Перед Save сначала нажми Apply changes: незавершённый ввод Inspector ещё
не является изменением документа. Для больших старых ландшафтов открытие
сцены/Play/Stop может занимать время на чтение OBJ и построение BVH.

Это базовый редактор с компоновкой как у Unity. В этой версии нет вложенных
Transform-parent связей, Timeline и Unity-компонентов.
Hierarchy содержит корневые объекты. Выбор работает через список; Focus selected
приближает камеру к объекту. Реальный viewport встроен в центральную панель через
Win32 SetParent; на ошибке встраивания смотри Console, не картинку-заглушку.

КАМЕРА И СВЕТ
Кликни по центральному окну, чтобы оно получило клавиатурный фокус.
WASD — перемещение, Space / Ctrl — вверх / вниз, Shift — ускорение.
Правая кнопка мыши — смотреть; R — сброс камеры.
Q / E — шаг по W, по умолчанию 0.1.
F1 / F2 — поворот света Y, F3 / F4 — X, F6 / F7 — Z.
F5 — перезагрузка скриптов во время Play.
Esc закрывает viewport; сам редактор остаётся и может запустить его снова.

ВОКСЕЛИ И ПОЛИГОНЫ
Воксели — отдельный ECS-компонент VoxelRenderer у того же Entity: позиции,
повороты, масштаб, W и скрипты общие с полигональными объектами.
У одного объекта одновременно могут быть model и voxels.
Рендер: GPU grid ray marching / 3D DDA по RGBA8 3D-текстуре. Это прохождение
луча через клетки, а не тысячи отрисовываемых кубов и не перевод вокселей в OBJ.
Пустая клетка пропускается; первая заполненная клетка даёт цвет и нормаль грани.
Если ближняя плоскость камеры уже внутри вещества, луч ищет его выход.
Освещение соответствует повороту света полигонального прохода:
0.6 + 0.4 * dot(normal, lightDirection), то есть нижняя грань темнее верхней.

Полигональный проход пишет обычный depth buffer. Воксельный шейдер записывает
проекционную глубину найденной поверхности через gl_FragDepth в тот же буфер.
Поэтому полигон перед вокселем закрывает воксель, а полигон за ним закрывается
вокселем. Поддерживаются поворот и неравномерный, в том числе отрицательный,
масштаб. Нужен драйвер с OpenGL 2.1+, GLSL 1.20 и 3D-текстурами.
Если драйвер не поддерживает шейдеры, в Console/engine.log выводится ошибка;
полигональная сцена продолжает работать.

MAGICAVOXEL .vox
Import file → выбери .vox → двойной клик по файлу в Project.
Или укажи путь в поле Voxel file в Inspector и нажми Apply changes.
В JSON сцены можно использовать "model":["assets/vox.vox"] либо
"model":[null], "voxels":[{"path":"assets/vox.vox", "cellSize":0.1}].
Палитра читается из RGBA, без неё используется стандартная палитра VOX.
Оси переводятся из Z-up MagicaVoxel в Y-up движка. Размер клетки по умолчанию
0.1. Геометрия центрируется вокруг позиции объекта.
SIZE/XYZI/RGBA/PACK и nTRN/nGRP/nSHP поддерживаются. Видимые экземпляры
иерархии объединяются с учётом переносов, поворотов и скрытых слоёв.
Для анимации используется первый по номеру кадр, а не проигрывание анимации.
Без иерархии загружается первая модель; отдельную модель можно выбрать:
"voxels":[{"path":"assets/scene.vox", "modelIndex":0, "cellSize":0.1}].
Максимальный размер объединённой сетки — 256 по каждой оси. Большую сцену
раздели на отдельные файлы или выбери modelIndex. MATL-параметры читаются,
но PBR, эмиссия, стекло и эффекты рендера MagicaVoxel не воспроизводятся.

ЧЕТВЁРТОЕ ИЗМЕРЕНИЕ
Сохранён формат .4d: несколько OBJ-слоёв с разделителем +. Центр слоя i
расположен на локальном W=i*layerSpacing, шаг по умолчанию 0.1.
positions[i].w задаёт сдвиг по W, scales[i].w — масштаб по W (по умолчанию 1).
Новый массив rotations4D содержит {"xw":0,"yw":0,"zw":0} на каждый объект.
Углы в градусах; сначала масштаб XYZW, затем повороты XW, YW, ZW,
затем обычные XYZ-повороты и перенос XYZW. Q/E меняют W камеры.

При нулевых 4D-углах выбирается исходный OBJ-слой без перестройки. Иначе
каждый треугольник поверхности протягивается через W-интервал своего слоя,
и вычисляется пересечение с W камеры. Это явно заданная модель слоёв,
а не интерполяция вершин между разными OBJ и не автоматическое создание
замкнутого 4D-тела. Различные соседние слои могут иметь разрывы на стыках.
Результат кэшируется до изменения W, масштаба или 4D-поворотов.
Физика по-прежнему трёхмерная: взаимодействует с текущим срезом.

Демо map-voxel.json содержит:
- полигональный пол;
- вращающийся голубой воксельный шар;
- оранжевую полигональную балку, проходящую через шар;
- передний полигональный куб и падающий куб с Rigidbody;
- отдельный воксельный участок ландшафта.

ФОРМАТ .vxl.json
{
  "size": [32, 32, 32],
  "cellSize": 0.1,
  "generator": "sphere",
  "color": [55, 165, 235, 255],
  "cells": [[16, 16, 31, 255, 180, 40, 255]]
}

size — целочисленные размеры сетки. cellSize — размер клетки в локальных
единицах; сетка центрирована вокруг позиции объекта. generator необязателен:
sphere, terrain или solid. Без него изначально все клетки пустые.
cells — необязательные изменения после генератора, каждая запись:
[x, y, z, r, g, b, a], координаты целочисленные, RGBA в диапазоне 0..255.
Alpha 0..127 — пустая клетка, 128..255 — непрозрачная. Полупрозрачности нет.

К старому формату карты добавлены параллельные массивы:
"voxels": [null, "assets/VoxelSphere.vxl.json"],
"active": [true, true],
"visible": [true, true].
Длина каждого массива равна длине model. Не добавляй эти массивы, если
воксели не нужны: старые карты поддерживаются без изменений.
Можно задать настройки компонента:
"voxels": [{"path":"assets/VoxelSphere.vxl.json", "enabled":true, "wSize":0.1}]
wSize ограничивает видимость интервалом W вокруг позиции объекта; без него
воксельный объект виден во всех W. Полигональные .4d по-прежнему работают слоями.

PYTHON API
from engine_runtime import Behaviour

class Script(Behaviour):
    def start(self):
        self.ball = self.world.instantiate(
            None, name="Runtime voxels",
            position=(0, 2, 0), scale=(1, 1, 1),
            voxels="assets/VoxelSphere.vxl.json",
            scripts=["scripts/voxel_spin.py"]
        )
        self.ball.set_voxel(20, 20, 39, (255, 100, 0, 255))

    def update(self, dt):
        self.ball.rotate(y=15 * dt)
        if self.world.input.pressed("X"):
            self.ball.set_voxel(20, 20, 39, (0, 0, 0, 0))

entity.add_voxels("assets/VoxelSphere.vxl.json") — добавить/заменить компонент.
entity.add_voxels("assets/vox.vox") — загрузить MagicaVoxel вместо JSON.
entity = self.world.instantiate("assets/vox.vox", position=(0,2,0))
four = self.world.instantiate("assets/spherecube.4d", w=0, scale_w=2,
                              rotation4=(20,0,0))
four.rotation4.x += 15 * dt  # угол XW; .y — YW, .z — ZW
four.w += 0.1               # положение по четвёртой координате
four.scale_w = 2            # толщина слоёв по W
entity.voxels.enabled = False — отключить его рендер.
entity.voxels.w_size = 0.1 — ограничить W-интервалом.
entity.set_voxel(x,y,z,rgba) — изменить клетку; обновление текстуры на следующем
кадре. Изменения игрового скрипта остаются в памяти, .vxl.json не перезаписывается.
Имеющиеся world.instantiate / destroy / load_scene, Rigidbody, триггеры и .4d
сохранены. Полное описание прежней физики: legacy/README-physics-v3.txt.

ПОТОКИ И ОГРАНИЧЕНИЯ
Native UI и render/physics thread разделены. Редактор — отдельный процесс.
Загрузка ассетов и расчёт 4D-среза используют worker threads. Поток рендера
ожидает новый срез перед загрузкой геометрии; это не асинхронная анимация.
Большие .4d при вращении и перемещении по W могут снижать FPS. Python threads
не дают параллельного исполнения Python-кода на нескольких ядрах из-за GIL.
Все вызовы OpenGL и изменения ECS
выполняются в потоке движка; передача команд идёт через локальный TCP-канал
с ключом сеанса. Самостоятельно мутировать ECS из произвольного Python-потока
нельзя. GPU обрабатывает лучи параллельно. Наличие Python threads не снимает GIL.

Максимум 4096 сущностей; до 32 видимых воксельных
чанков, каждый до 256x256x256 клеток. Один такой RGBA8 чанк занимает около 64 МиБ
до копий CPU/GPU. Это плотные сетки, не бесконечный sparse voxel world/SVO.
Каждый чанк имеет отдельный проход по экрану. FPS зависит от GPU, разрешения,
заполненности и количества чанков. Высокое число чанков требует дальнейшей
оптимизации. Изменённый чанк сейчас целиком переотправляется в 3D-текстуру.

Воксельная графика не создаёт точный поклеточный Collider автоматически.
Можно вручную задать BoxCollider нужного размера для воксельного объекта,
но он не учитывает пустоты. Точная полигональная коллизия ландшафта работает
через MeshCollider. Это не полная четырёхмерная физика: используется 3D-срез.

ПРОВЕРКИ ЭТОГО ОБНОВЛЕНИЯ
- 21 переносимый тест: VOX-палитра, оси и иерархия, некорректные файлы,
  4D-преобразования, управление gizmo, undo/redo, старые сцены и транспорт.
- 7 регрессионных тестов физики с исполнением настоящего ASM-ядра через Win64 ABI.
- Проверка Edit/Play/Stop, остановленных скриптов, замены объекта и отката ошибки.
- Настоящий OpenGL/Mesa: компиляция GLSL; глубина в обе стороны; поворот,
  неравномерный масштаб, W-видимость, пустые клетки и положение за камерой;
  выход из заполненного объёма, отсутствие дыр на границах клеток, твой .vox.
- OpenGL-отрисовка ручек Move, Scale, Rotate и 4D rotate с проверкой
  восстановления матриц и состояния после наложения интерфейса.
- Настоящая многослойная .4d: W-масштаб, пересчёт и кэш среза, удаление старой
  геометрии, отсутствие утечек. Прежние ASM-модули в 2.1 не изменялись.
Windows EXE, интеграцию Tk/Win32 и resource compiler здесь запустить нельзя;
их нужно проверить после локальной сборки на твоём Windows.
