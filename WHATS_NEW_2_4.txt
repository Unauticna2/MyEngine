MYENGINE 2.4 — инструкция

УСТАНОВКА
Закрой окна редактора и игры. Распакуй MyEngine2_4_update.zip поверх 2.3
с заменой файлов или распакуй полный MyEngine2_4.zip в новую папку.
Запусти build.cmd, затем start_hub.cmd / start_editor.cmd.
Нужны Windows x64, VS 2022 Desktop development with C++, Windows SDK
и обычный CPython 3.11–3.13 x64 с Tk. При первой настройке: setup_python.cmd.
Архив содержит исходники: MyEngine2.exe и Slice4D.dll соберутся у тебя.
Старый MyEngine2.exe с Python-файлами 2.4 использовать нельзя.
Сборщик не завершает запущенные процессы принудительно.

1. ЧЕТЫРЕ ТЕМЫ
Theme в редакторе и хабе:
• Light — светлая дневная.
• Dark — тёмная ночная.
• Automatic — Light с 07:00 до 20:00, Dark в остальное время по локальным
  часам компьютера. Переключается без перезапуска.
• Sunlight — белый фон, чёрные жирные увеличенные надписи, более толстые
  границы и соединения нод. В окне редактора видимые объекты получают
  белую рамку по их габаритам. В обычном запуске игры эти рамки не рисуются.
Настройка сохраняется между запусками. Это повышает контраст интерфейса;
программная тема не меняет физическую яркость экрана и солнечные блики.

2. УСКОРЕНИЕ 4D
Оконный цикл, native-сцена и физика по-прежнему на MASM.
Новый Slice4D.cpp собирается в Slice4D.dll: расчёт сечения и закрывающих
граней перенесён из Python в C++17. ctypes освобождает GIL, пока DLL считает.
Один постоянный worker выполняет очередь; запросы старых сечений одного
объекта заменяются последним. Рендер показывает предыдущий готовый срез
до прихода следующего. Источники и готовые срезы имеют ограниченные кэши.
W-шаг остаётся 0.1 по умолчанию. XW/YW/ZW, W-масштаб, нормали и UV сохранены.
Если DLL исключена из игровой сборки или отсутствует, будет предупреждение
в Console и медленный Python fallback. Для ускорения оставь DLL в сборке.

Локальный замер Linux x64, g++ -O3, spherecube.4d, углы (20,15,0), W=0,
пять прогретых повторов: медиана Python 0.280 с, native 0.0073 с, ~38 раз
для этого расчёта. В обоих случаях 6732 треугольника и одинаковые границы.
Это не замер FPS и не обещание того же ускорения на Windows/других моделях.
Физика всё ещё работает с текущим 3D-сечением, не с полноценным 4D-объёмом.

3. СОБСТВЕННЫЕ НОДЫ
Создай Python-файл в plugins/nodes своего проекта:

def register(api):
    api.define(
        'My.Double', title='Double', hint='Умножить число на два',
        params={'value': 1}, inputs={'value': 'number'},
        outputs={'value': 'number'},
        expression=lambda c: '(' + c.input('value') + ') * 2')

Blueprints → Reload nodes. My.Double появится в списке Add node.
В params указываются значения по умолчанию для входов и другие параметры.
Порты: number, bool, exec. expression возвращает строку Python-выражения;
у такой ноды один выход данных. action возвращает код действия (строку или
список строк); вход in:exec, необязательный выход next:exec.
Для связанного входа/значения по умолчанию — c.input('value'). Для безопасно
заключённого в кавычки параметра пути/имени — c.literal('path').
В сгенерированном коде доступны self.entity, self.world, dt.
Примеры: plugins/nodes/example_nodes.py — время, синус, чтение данных, лог.
Граф scripts/data_spin.blueprint.json читает speed и вращает объект.
Generate Python обновляет только регион MYENGINE_BLUEPRINT.
Сгенерированному скрипту плагины редактора для запуска не нужны.
Сами плагины — обычный Python и загружаются только с разрешением проекта.

SCRIPTABLE OBJECTS
Assets / extensions → New Scriptable Object.
Двойной клик по *.scriptable.json в Project открывает редактор данных.
JSON хранит тип, schema и data. Типы полей: float, int, bool, string,
vec3, list, object, any; доступны required/default/min/max/choices.
Схема проверяется при загрузке, изменении и сохранении.

settings = self.world.resources.scriptable('assets/data/Mover.scriptable.json')
speed = settings['speed']             # общие данные в кэше этого мира
own = self.world.resources.scriptable('assets/data/Mover.scriptable.json', clone=True)
own['health'] = 25                    # независимая копия
own.save('путь/к/новому/файлу.scriptable.json')

Изменение значения в памяти само по себе файл не перезаписывает.
Списки и словари при чтении копируются: изменённое значение нужно присвоить
обратно через settings['field'] = value. Для свежей версии изменённого
на диске ассета перезагрузи сцену; автоматического hot reload данных нет.

4. ПРЕФАБЫ И ДОВЕРЕННОСТЬ
Выдели один объект или несколько через Ctrl в Hierarchy.
Assets / extensions → Save selected as prefab → *.prefab.json.
Instantiate prefab или двойной клик по префабу добавляет группу в сцену.
Позиции сохраняются относительно первого выбранного объекта; имена новых
объектов автоматически становятся уникальными. Операция поддерживает Undo.

objects = self.world.instantiate_prefab(
    'assets/prefabs/Pair.prefab.json', position=(0, 2, -3), prefix='Pair')
objects[0].position = (1, 3, 0)
objects[0].destroy()

Возвращается список Entity. Скрипты, размеры, физика, W, параметры теней
и флаги доверия сохраняются. Ошибка создания откатывает созданную группу.
Это независимые экземпляры: live-связи с исходником, prefab variants,
наследования и parent/child-трансформов в этой версии нет.

Под «доверенностью» реализовано разрешение выполнять скрипты:
• Inspector → Allow scripts on this object — флаг scriptTrusted.
• Assets / extensions → Project script permission — общий переключатель.
• trusted=False при instantiate / instantiate_prefab отключает скрипты
  создаваемого объекта/группы до импорта их Python-файлов.
Проекты, загруженные кнопкой GitHub packages, получают общий запрет скриптов
до явного включения. Своим существующим проектам разрешение оставлено.
Общий запрет сохраняется и в игровой сборке; флаги объектов тоже.
Это разрешение запуска, а не изолированная песочница: разрешённый Python
имеет обычные права процесса. После изменения разрешений сцена перезапускается.

5. ТЕНИ И СВОЯ ТЕКСТУРА СОЛНЦА
Assets / extensions → Shadows / sun texture.
Карта направленного света общая для полигонов и воксельного реймарчинга:
они отбрасывают тени друг на друга. Срез .4d участвует как обычная геометрия.
Inspector: Cast shadows / Receive shadows отдельно для каждого объекта.
Разрешение карты: 512, 1024, 2048. Distance — радиус вокруг камеры;
Bias — смещение сравнения глубины. Мягкость края — фильтр 3×3.
Это один направленный источник с ограниченной областью теней, без каскадов.
Слишком большой Distance уменьшает детализацию. Тени требуют дополнительного
прохода сцены; для слабого GPU можно выбрать 512 или отключить их.

Sun texture: PNG/BMP; путь можно выбрать и импортировать кнопкой.
Поддерживается прозрачность PNG; Black as transparent пригодится для масок
на чёрном фоне. Angular size — размер в градусах, brightness — яркость.
Солнце видно на небе в направлении света, фон может быть без skybox.
Изображение солнца не меняет силу света само по себе.
F1/F2 вращают свет вокруг Y, F3/F4 — X, F6/F7 — Z.

self.world.set_sun({'texture':'assets/skybox/sunmask.png',
                    'size':12, 'brightness':1, 'blackAsAlpha':True})
self.world.set_sun(None)
self.world.shadows['enabled'] = False
self.entity.cast_shadows = False
self.entity.receive_shadows = False

6. ИСКЛЮЧЕНИЯ СБОРКИ
Build game → Exclude file extensions / Exclude individual project paths.
По умолчанию из Data исключены .c, .cs, .cpp, .asm. Список можно изменить.
Exclude source / library… добавляет отдельный файл. Можно добавить .dll,
.lib, .h или маску вроде native/debug/* в список путей.
Правила хранятся в build-options.json проекта. Исходный проект не удаляется.
Проверяются ссылки сцен и префабов; удаление используемой модели, текстуры
или прикреплённого скрипта останавливает экспорт. Зависимости произвольных
Python import/ctypes заранее полностью определить нельзя.
Правила управляют упаковкой проектных файлов, не компиляцией .cs или .asm.
Bundled Python и обязательные файлы движка добавляются отдельно.
Slice4D.dll можно исключить явно, получив Python fallback.
Формат распространения прежний: один Game.exe рядом с одной папкой Data.

ДЕМО И ПРОВЕРКИ
start_features24.cmd → Play. Объект читает скорость из Scriptable Object;
P создаёт префаб из двух физических коробок, O удаляет созданные группы.
Сцена содержит полигон, воксельную сферу, повёрнутый 4D-объект и своё солнце.
Все новые исходники и примеры лежат в обоих архивах.

Проверено в Linux:
• 55 unit-тестов, включая сравнение native/Python сечений, закрытые грани,
  полости, отрицательный W-масштаб, префабы, схемы данных и генерацию нод.
• 19 проверок runtime с реальным ASM-ядром физики через ABI-мост,
  плюс Edit/Play/Stop и демонстрационная сцена.
• Настоящий OpenGL через Mesa/EGL: взаимные тени полигонов и вокселей,
  флаги теней, текстура солнца, окклюзия и отсутствие дыр внутри вокселей.
• NativeScene.asm собирается MASM-совместимым JWasm без ошибок.
Полный Windows EXE, связку MSVC/link и оконный интерфейс Windows здесь
запустить нельзя; окончательный запуск build.cmd и UI требуется на Windows.
