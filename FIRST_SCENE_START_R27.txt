НОВАЯ НОДА: FirstSceneStart (First Scene Start)
Запускает подключённую цепочку при первом посещении сцены за один
запуск игры. У каждой сцены своя отметка, которая хранится только в RAM.

Пример:
  Запуск игры -> A: FirstSceneStart сработает.
  A -> B: в B тоже сработает.
  B -> A: в A повторно не сработает.
  Перезапуск игры -> A: снова сработает.

В редакторе Stop -> Play считается новым запуском игры.
F5 и повторная загрузка сцены в текущем Play отметку не сбрасывают.
Редактирование сцены без Play не расходует первое срабатывание.

КАК ДОБАВИТЬ
1. Открой Blueprints, выбери FirstSceneStart -> Add node.
2. Соедини next с in нужного действия: Print, Spawn, UIShowSlide и т.д.
3. Generate Python; прикрепи .py к объекту-контроллеру в этой сцене.
4. Сохрани сцену и запусти Play.

Готовый пример: scripts/first_scene_start.blueprint.json и соседний .py.
Он пишет две строки: Start при обычном старте объекта, FirstSceneStart
только при первом посещении сцены за текущий запуск.

ПОРЯДОК И ГРАНИЦЫ
Обычный Start остаётся. При первой обычной загрузке сначала вызываются
Start активных объектов сцены, затем их FirstSceneStart.
В графе может быть один Start и один FirstSceneStart одновременно.
Все прикреплённые к сцене обработчики получают событие; если нужно
одно общее действие для сцены, прикрепи граф к одному контроллеру.

Позднее созданные через Spawn объекты получают обычный Start.
FirstSceneStart предназначен для скриптов, загруженных вместе со сценой.
Неактивный объект первой загрузки получит событие при включении в ходе
того же посещения. Отключённые/недоверенные скрипты не выполняются.

Загрузка PNG в том же запуске игры сохраняет уже отмеченные сцены.
При загрузке PNG в новом запуске FirstSceneStart вызывается один раз
после восстановления скриптов. Обычный Start при восстановлении PNG
по-прежнему не повторяется. Список посещений в PNG не записывается.

Если загрузка новой сцены завершилась ошибкой, она не считается
посещённой. После исправления сцены событие сможет сработать.
Идентичность сцены определяется её путём, а не заголовком окна.
Для редакторского preview используется путь исходной сцены, поэтому
возврат из другой сцены не даёт ложного повторного FirstSceneStart.

PYTHON
from engine_runtime import Behaviour

class Script(Behaviour):
    def first_scene_start(self):
        self.world.log('Первое посещение этой сцены за текущий запуск')

Старые блюпринты поддерживаются: добавь ноду и Generate Python в тот же
файл. Код вне сгенерированного региона сохраняется. Ручной обработчик
first_scene_start и соответствующая цепочка блюпринта могут сосуществовать;
сначала выполняется ручной обработчик, затем цепочка. Не вызывай
_bp_first_scene_start вручную, если используешь этот автоматический вызов.
